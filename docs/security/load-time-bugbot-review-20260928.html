BUG-1 / P2Stored native session can trap sign-in in a redirect loop during an auth outage.

src/components/auth/native-auth-hub.tsx:173-178 now routes to continue as soon as getSession() returns a stored user. That local user does not prove getUser() can currently succeed. src/app/auth/continue/page.tsx:44-48 returns to sign-in after its bounded getUser() polling returns null and does not clear or suppress the stored-session redirect. With an unexpired cached session and offline/rejected auth reads, sign-in routes to continue again, repeatedly preventing access to the credential form. Before this change the passive getUser() check failed and left the form accessible.

Keep the form available immediately and only redirect a cached-session candidate after a bounded validated user check; alternatively make continue failure explicitly suppress passive routing on the return. Avoid deleting a valid session merely for a transient network error.

Open. Add integration-level auth UI coverage with a cached session user, unavailable getUser(), and continue-to-sign-in return. Existing NativeAuthHub coverage tests only a rejected getSession() and mocks out the actual timeout. Verify successful stored-session routing also remains functional.
BUG-2 / P2A pre-write tour fetch can undo post-write cache invalidation.

src/lib/resident-tour-sync-client.ts:38-39 installs every successful response and sets a new 15-second TTL. notifyResidentToursChanged() at line 66 only resets the timestamp. A dashboard fetch can remain pending after navigation to Tours. Scheduling or cancellation then invalidates the cache while the dashboard listener is unmounted. The earlier read settles with pre-write data and marks that data fresh. Returning to Dashboard within the TTL serves a cancelled tour or omits the newly scheduled tour. The coalesced forced refresh fixes this only while a dashboard listener is mounted; the write itself does not queue that refresh.

Track invalidation generation per entry. An older flight must not publish fresh cache state after a write, and a subsequent reader must receive a run started after invalidation rather than join the obsolete flight.

Open. Add a deferred-response test: begin read, invalidate after a successful simulated write with no dashboard subscriber, resolve old read, then read again and require a post-invalidation request/result. Existing cache tests cover invalidation only after the first read has finished.
