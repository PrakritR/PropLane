Authorization and replay risks

High consequence if blindly replayed: 20260918153000_workspace_permissions.sql updates every pending or accepted account_link_invites row by merging {"addProperties":true}. JSONB right-hand precedence overwrites an explicitly false grant. This is an unrelated broad access expansion, even when all referenced columns already exist. An explicit get-to-production instruction authorizes necessary release work; it does not independently authorize this unrelated grants change. Do not execute this UPDATE or certify that it ran from structural evidence alone.

The role and calendar migrations contain no data backfill, but dropping/re-adding a CHECK can fail against existing invalid values and takes locks. Verify existing definitions first; if already equivalent, prefer truthful documented history reconciliation after proving every effect, rather than needless DDL. The reminder migration widens three checks, adds an offer-expiry column/index and rewrites the offer-status check. The supplied evidence does not cover these objects. Never delete either duplicate record or reapply by name alone.
