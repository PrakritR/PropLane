Blocking findings

  1. P1: a fresh capture can bless a recovery bypass while retaining the pinned body. Script lines 74-80 and 92 pin function body hashes but accept any 64-hex full-definition digest and do not pin exact trigger definitions. For example, a function-local SET proplane.account_recovery_internal = 'on' on account_recovery_write_guard() leaves its body unchanged. The outer identity check can see an unset bypass setting, while entering the function sets it to on and immediately returns NEW. The captured full-definition hash differs but is accepted; runtime equality merely verifies that this unreviewed definition remains unchanged. A changed trigger WHEN clause similarly preserves name, event type, function and enabled state. Pin independently reviewed full definitions or explicitly validate identities, language, security mode, configuration and exact trigger definition against reviewed constants. Add negative coverage for a function-local bypass, changed search path and changed trigger WHEN clause.
  2. P1: replication mode can silently suppress both reviewed triggers. Script lines 120-125 reject the recovery bypass GUC, but do not require session_replication_role = origin. Both required triggers have enabled state O; a privileged apply connection using replica mode skips them. A no-op invitation update then passes the full-row digest even when the recovery guard should reject it. Require origin mode before replay and include a local rehearsal that proves replica mode fails before DDL and active recovery still aborts in origin mode.
  3. P2: outer dollar delimiters are not protected by SQL literal escaping. Script lines 130-147 embed captured strings in fixed $baseline_before$ and $baseline_after$ DO bodies. A historical migration name containing the corresponding delimiter passes snapshot validation but terminates the outer dollar string even though its apostrophes were escaped. This produces malformed SQL for an otherwise valid captured name. Executable injection is not established by this source review; the ordinary result is a parse failure and rollback. Construct each DO body first and choose a delimiter absent from the complete body, or reject delimiter collisions before emitting artifacts. Cover both delimiters in historical names and catalog text.
  4. P2: expected existing role/provider constraints are not validated before convergence. Script lines 84-92 require constraint validity generally, but do not require the two existing team-role checks or provider check to have their reviewed definitions. A fresh capture containing a different allowed-value set passes preparation and runtime capture equality, then canonical DDL silently replaces it. The approved plan expressly requires refusal of unexpected existing check values. Require the reviewed canonical definitions and expected presence for those named constraints before replay; test a changed and a missing constraint. This is separate from postconditions, which already assert the intended resulting definitions.
