## Findings and resolution

- **High — selection actions became unreachable.** The initial surface required `onBulkClear`, but all existing consumers omitted it; some also render `bulkActions=null` until rows are selected. The surface now enters Select mode from an explicit clear callback independent of action availability. Clear callbacks were wired across consumers; fallback clearing remains for legacy callers. Behavioral tests cover a null initial action group, Select visible, disabled rows, Done, and actions preceding rows.
- **High — identity changes could accept stale source state.** Applications and lease read-success flags survived actor changes; late failures reset another actor's readiness, and lease JSON parsing lacked a second identity check. Flags reset with scope generations; late responses/errors cannot mutate the new scope. Inbox cache generations also reject A→B→A stale reads and stale 401s. Property fetch in-flight and TTL reuse is scoped by viewer, and session reset invalidates outstanding work. Tests drive delayed failures and body parsing across identities.
- **Medium — retry discarded usable records.** Resident and inbox retries cleared successful lists. Same-viewer resident snapshots remain visible with an error banner if refresh fails; inbox sources preserve their existing rows during retry. Unknown initial state uses loading rather than empty/add; failed initial reads do not show a false empty state.
- **Medium — former fixed bars moved below their lists.** Replacing fixed positioning alone made actions appear at the bottom of long pages. Standalone manager, resident, document, team and property-detail lists now compose their selection toolbar above rows through `PortalRecordListSurface`. Checkbox forms outside a list remain independent. The inbox action group also precedes the scrollable conversation list.
- **Medium — selection changes were not reconciled reliably.** Comparing accessible labels could miss replaced same-name records. The observer tracks actual keyed checkbox nodes; caller clear callbacks remove off-screen IDs too. Workspace and viewer changes exit selection. Native `hidden` attributes keep non-selection checkboxes out of the accessibility tree; hit areas are at least 44×44. DataList uses the same mode.
- **Medium — duplicate SMS directory requests and stale composer responses.** The inbox and composer now coalesce concurrent reads by viewer, with separate Response bodies per consumer. Direct-send refresh reuses the guarded loader; composer data includes its owning viewer so old responses cannot display after an identity change.
- **Medium — asynchronous archive cancellation was ignored.** Shared SMS archive/restore callers await server completion before local success, preserve selection on error, and show an error instead of claiming success. The archive implementation itself belongs to the security review.

Raw action groups show two actions and a keyboard-accessible More disclosure; existing adaptive action groups retain their own overflow behavior. Existing authorization, confirmations, and asynchronous button handlers remain attached to the original controls.
