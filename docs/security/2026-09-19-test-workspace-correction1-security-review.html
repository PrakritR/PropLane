C1-S1 / P1Authenticated pricing continuation still creates real Stripe sessions

src/app/api/manager/pricing-oauth-continue/route.ts:52,73,147; src/lib/stripe/manager-checkout.ts:32,35,95,132

A classified manager with a valid session and existing manager purchase id can submit a paid tier and billing cadence. The route provisions/loads the account, then calls createManagerCheckoutSession. That helper resolves Stripe prices and creates an embedded or hosted subscription session, returns its client secret/URL, and may upsert manager_purchases. It never traverses the newly guarded manager customer helper. Active, suspended, expired and flag-off classification all follow this path. This requires ordinary configured Stripe prices, not forged provider metadata.

Correction: Refuse classified identities before provisioning writes or price lookup in the authenticated route and at the shared checkout boundary. Resolve identity from auth/stored profile for existing accounts; preserve genuinely new ordinary signup. Do not rely on optional or model/body-supplied userId.

C1-S2 / P1Financial reconciliation and refunds still bypass the creation guards

src/app/api/portal/deposit-return/route.ts:50,68,92; src/app/api/manager/subscription/route.ts:94,103,127; src/lib/manager-stripe-subscription-sync.ts:27,36,57,63,106,122; src/app/api/stripe/webhook/route.ts:188,281; src/lib/comms-billing/credit-purchase.server.ts:191,221,294,298,313

For a classified account with an existing settled deposit and ledger Stripe charge id, deposit-return performs a real refund. Subscription GET retrieves live subscription state through several paths. A delayed signed invoice.paid calls applyScheduledDowngradeAfterInvoicePaid, which retrieves and updates Stripe without first resolving the stored owner. A delayed signed paid communication-credit session calls fulfillCommsCreditPurchase and the service-role fulfill_comms_credit_purchase RPC, crediting the wallet without classification. The original RPC writes billing account, purchase and adjustment rows; restrictive authenticated-client RLS is not an effect guard for this service-role path. Credit reversal also fetches a charge before it has selected a stored owner. These examples require pre-existing provider-backed rows or genuine signed events; they are not claims that a browser can forge a webhook.

Correction: Guard the actor plus server-derived resource owner for refunds; guard stored subscription owners before provider retrieval/update; reject or capture classified fulfillment before any wallet/purchase write. Trace all dispatch branches of the existing Stripe webhook through their first provider/business mutation. Preserve ordinary event retry/idempotency semantics. A classified terminal refusal must be acknowledged after evidence is retained, while classification/evidence failures remain retryable.

C1-S4 / P1Active classified users can cross the private data boundary

src/app/api/portal/applicant-ids/route.ts:28,33; src/app/api/portal/record-share-link/route.ts:65,68; src/lib/portal-record-share-links.server.ts:48,69,93,110; src/app/api/share/applications/[token]/route.ts:13,18; src/lib/portal-record-share-payload.server.ts

An active classified manager can query applicant-ids with a normal customer email and receive that profile manager_id: only the caller manager role is checked, and no target membership comparison occurs. Separately, an active classified manager can mint a share token for its own application/lease; the public share resolver checks revocation and token expiry only, and its payload loader has no durable classification boundary. Opening that token without a session exposes the private workspace record. The share token is legitimately obtained by the classified owner, not guessed. Suspending membership or flag-off does not invalidate that public resolution.

Correction: For identity lookup, resolve target membership and require the same private workspace for classified callers; normal callers must not receive classified targets. For application/lease share links, refuse classified public token mint/send and make token resolution fail closed for classified owner/creator/record provenance, including already-issued tokens. Ordinary public sharing stays unchanged. Keep internal private record links if already supported; do not invent a second public test-share system.
