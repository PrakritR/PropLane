Security boundaries checked

  • Authentication: Middleware deletes caller-provided x-pathname and x-requested-path, then derives trusted request headers. Redirect normalization rejects external/protocol-relative/backslash variants. Role guards continue to use role membership; deep-link preservation does not grant another role.
  • PII: Fee promotion opens identity only server-side after selecting the paid session's stored email/property draft, validates complete answers, and reseals before persistence. No identity values or raw tokens are added to logs or anonymous verification responses. Validation logging contains field names and record id only.
  • Lease evidence: Generation uses local-only edits followed by one awaited server write and restores the previous local row on refusal. Existing server signature and document-immutability guards remain authoritative. Optional local version/persistence options do not create a server bypass.
  • Uploads: The add-lease UI blocks replacing a sent/signed resident lease and continues to use existing upload/import functions. No PDF parser or storage permission weakening is introduced. Private source PDF ownership, active-content refusal, reviewed import receipts, and signed-body protection remain existing dependencies.
  • Availability: Public payloads remain room/date/count spans, without resident identity or application identifiers. Client freshness checks improve feedback; database placement arbitration remains the capacity authority.
  • Native and links: Shared web UI and existing paths serve the Capacitor shell. Email-only claim delivery works without sharing cookie/sessionStorage between WebView and external browser. No new in-app route prefix or native permission is introduced.
  • Test data: The seed helper now stores generated HTML text rather than the generation result object. It is a dev/test seed change; this review does not authorize a production seed or repair.
