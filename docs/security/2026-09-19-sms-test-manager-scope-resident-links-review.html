Manager scope

resolveSmsTestContext obtains active authenticated workspace capability and requires the independently resolved manager identity and testWorkspaceId to match. It reconstructs SMS access using that actor as the work-number owner and passes the authenticated workspace id. Owner mode retains owned records; combined mode adds accepted co-manager assignments with the existing per-owner, per-property permission map. Only the portal workspace selection is cleared; durable test classification and access grants remain on the context.

The optional resolver argument adds an exact test_workspace_id equality predicate to accepted incoming links. Carrier identity callers omit it and retain their existing owner-number and delegated boundaries. Query failures still throw. If the original context had combined access but workspace filtering leaves owner-only access, the test context is refused instead of silently downgrading. When both matching and nonmatching links exist, only matching links contribute to combined scope.

The existing loadAllManagerRows reads permitted owner ids and calls smsAccessAllowsRow before exposing applications. Co-managed applications require an assigned property and applications read permission (including the existing edit/delete-implies-read rules); owned rows remain available in combined mode. Ungranted domains and unassigned rows are denied. Clearing UI workspace narrowing removes a presentation filter without removing those permission checks.

The application row loader is owner-scoped rather than adding a test_workspace_id predicate to every query. Isolation continues to rely on the previously reviewed durable classification/migration invariant that accounts and their owned rows cannot cross test workspaces; this delta additionally filters accepted links. This scoped review does not re-attest deployed schema or migration state.

Resident links

get_resident_links accepts an empty strict input schema. The optional origin comes only from server-only AsyncLocalStorage SMS-test context when both workspaceId and appOrigin are present. Application transport entry points remain the authenticated SMS-test runner; the previously reviewed route derives appOrigin from deployment configuration, not Host, forwarded headers, model input or request body.

The exported residentLinks function retains its original channel-only signature and canonical/relative behavior. Only the tool handler passes the classified context origin to the private absolutize helper. Portal channel returns relative paths before considering an override. Ordinary off-platform turns without classified test context retain canonical production URLs. Vendor links are unchanged. Fixed resident paths contain no caller-selected host. The change affects navigation origins, not authorization to destination pages or provider delivery.
