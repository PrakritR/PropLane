## Direct Save billing evidence correction

The isolated target is application `AXIS-QA-RESIDENT-SAVE-BLOCK-1108` at property `qa-resident-save-block-1108-house`, with an unsigned Draft lease and zero applicable fees. The v13 and v25 Save observers also saw household-charge POST acknowledgements, but inspection found no target-fixture charges in those payloads: the scoped batch belonged to another fixture and the larger batches were background mirrors. Those acknowledgements are not evidence that this target's charges were written. Earlier raw receipts remain unchanged; their prior attribution is corrected here.

For an approved, non-manually-added application without an executed lease, Save invokes `recordApprovedApplicationChargesScoped` with no `atSigningOnly` option. `recordApprovedApplicationCharges` returns before generating a tenancy schedule; a zero application fee creates no fee row. When the target has no existing scoped charges or rent profiles, `mirrorApplicationHouseholdChargesAwait` succeeds without a POST. This is the expected unsigned no-op, not missing target billing. Explicit at-signing generation for a Sent lease and existing manually-added tenancies are separate paths. Target billing generation/write behavior remains supported by its focused regressions and separately identified signed lifecycle/payment evidence, not these background acknowledgements.
