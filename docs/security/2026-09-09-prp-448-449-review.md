# PRP-448/449 final security review - 2026-09-09

Status: clean after review fixes.

The route still applies its existing role, property, resident, document
immutability, signature-role, and signature-hash checks before calling the new
RPC. The RPC is executable only by `service_role`; browser ids do not grant
write authority.

Lease persistence and notification intent insertion occur in one PostgreSQL
transaction. Existing rows are locked and compared by `updated_at`, while a
new-row conflict returns `stale`. A stale writer therefore cannot replace a
newer signature, execution hash, document body, or notification transition.
The stored timestamp advances beyond both the prior token and the submitted
timestamp, including same-clock-tick writes.

The SQL validates the event against the persisted lease manager and lease id.
Manager deliveries must target that manager. Resident user id and normalized
email, when supplied, must match the lease columns, and the canonical recipient
key must match the stored user-id-first identity. Required signature-transition
audiences fail closed. Event-key conflicts are accepted only for the same lease
event identity.

The worker claims due pending, failed, and deferred rows with a status and
due-time compare-and-swap. Its final update repeats that guard, surfaces database
errors, and does not overwrite or count a stale finalizer. A crash leaves the
row claimed for five minutes, after which it is eligible again. Downstream
delivery uses a deterministic message id, which is the retry safety contract
when delivery succeeds before final status persistence.
