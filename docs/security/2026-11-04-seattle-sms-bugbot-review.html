Bounded review coverage

  • Acceptance: signed provider account and normalized wire identity are checked before durable persistence and acknowledgement. Duplicate SID requires matching wire pair, original payload digest, runtime and account. The worker cannot run before a persisted envelope exists.
  • Replay and claim safety: SQL claim increments attempts only on accepted, due, unexpired work. Checkpoint and preparation require current token and unexpired lease. Effect/delegation are monotonic; a stale worker cannot save after recovery changes its lease. Exception recovery rereads persisted stage, avoiding replay after a lost checkpoint response.
  • STOP/START/YES: the control decision is persisted before timestamp and idempotent control RPC work. A suppressed YES replay retains START after suppression changes. A normal unsuppressed YES continues toward confirmation. STOP and HELP precede ordinary rate limiting. A failure after control application cannot reroute that message into a tool confirmation.
  • Unknown provider outcome: the dispatcher claims each persisted ordered bubble before submission. Only definite pre-provider refusals retry the same bytes; exceptions with potential submission become delivery_unknown. Submission lease expiry never blindly resends. Unknown execution effects likewise freeze for reconciliation.
  • Callback races: service-only callback binding requires opaque token, runtime, account, wire pair and consistent SID. A callback arriving before the worker outcome changes the reply to accepted; the worker outcome update is conditional on submitting and cannot overwrite it. A different returned SID creates a reconciliation refusal. Late acceptance reopens only a delivery_unknown envelope whose replies are all accepted/prepared and whose expiry has not passed. Callback processing sends nothing.
  • Recovery and thread routing: shared recovery checks the original workspace owner, archive status and current shared-line eligibility instead of substituting the physical shared-line owner. Verified-admin continuation remains narrow. Delegation observes the existing receipt instead of reentering shared routing. Existing manager receipt/outbox billing remains responsible for delegated effects.
  • Retry deadlines: envelope attempts, per-bubble attempts, backoff, lease and expiry are bounded. Cron checks its start deadline between rows and shares it with existing receipt recovery. A true uncertain effect remains an explicit operator item, not an automatic duplicate.
