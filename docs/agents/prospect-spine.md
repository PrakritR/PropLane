# Prospect spine (design-1112)

The one place a person who is not yet an account holder is written down. Code: `src/lib/prospect-spine/`.

## Invariants
- **Phone is the identity.** `sms_phone_contacts` (one row per phone) carries claims (`email`, name), proof (`verified_at`, set only by a code or `phone_auth_bind`), `first_source`, `linked_at`. A name or an email is never a key.
- **One writer.** `recordInbound` (`record.server.ts`) writes every inbound turn: ONE thread per person per workspace through `resolve_or_create_conversation` (never a bare upsert), stamped `rootHouseId`, per-turn `houseId` / `roomId` / `source`, row `prospectContext`, `prospectPhoneKey`. Idempotent on `eventId`. A legacy `sms_notice_*` row is adopted, never duplicated.
- **Context table.** `prospect_contexts` = person (phone key or platform handle) x workspace x property x room x source, with counters and the thread id. Service-role only (RLS on, no client grant).
- **Context evidence, in order** (`resolveInboundContext`): the router's property (home lock / entry code) -> an entry code in the text -> a house the text names (`identifyHome`) -> the sender's current residency (property + room from the occupancy snapshot). Nothing resolved = no tag, never a guess.
- **Staff read what they run.** `CommunicationScope.staffWorkspaceOwners` (filled from `loadServiceStaffWorkspaces` + the viewer's own seat) lets staff of the ACTIVE `is_service` workspace read its owner's conversations, house-less or not. A self-serve co-manager never reads a house-less thread. A `house_scope = all` seat with no explicit ids expands to the workspace's houses. Every SMS-projection read pre-filters its candidate owners through `communicationCandidateOwnerIds` (`scope.ownerIds` plus the ACTIVE workspace's staff owner) rather than `scope.ownerIds` alone, or staff with no house granted were dropped before the decision ran: that is a candidate pre-filter only — `conversationVisible` stays the decision, and a viewer with no staff entry widens nothing.
- **Every inbound alerts** (`alertOpsOfInboundText`): text to each staff phone (transactional: not held in quiet hours; STOP still wins) carrying that phone's reply handle (`mintReplyHandle`, Package C), email, and a push per staff account. Nobody listed = PropLane's admin phones, never "skipped".
- **Replies are never lost to the wallet.** On a managed workspace, a prospect reply the normal send refused is sent by PropLane itself (`sendAsPropLaneAfterRefusal` -> `sendPlatformLeadText`, PropLane pays). STOP, quiet hours and shielded accounts are never overridden. Self-serve workspaces stay fail-closed. Idempotent per reply.
- **Nothing fails silently.** `recordDeliveryIssue` stamps `row_data.deliveryIssue {at, direction, reason, messageId}` (reasons are scrubbed of numbers and ids); with no thread it raises one Attention item. Shown under the inbox Filter "Delivery issues" and in the contact pane. A later delivered send clears it (`clearDeliveryIssue`). Sources: the leasing reply refusal, the burst worker's failure branches, provider `failed` statuses, envelope `needs_review` transitions, the inbound worker's catch.
- **Link on a verified phone only.** `linkAccountToProspectRecord` runs after `phone_auth_bind` and after an SMS signup: the profile must hold the number with `phone_verified_at` and `phone_auth_owners` must name exactly that account. It sets `sms_phone_contacts.user_id`, writes the account-side mirror thread (resident scope, `ws:<workspace>` key) with the earlier turns, and stamps `residentUserId` on application rows with the same phone that have none. The manager-side thread keeps its key (`tel:` unless the account is tied to the workspace by a lease, application or vendor record), so the manager still sees ONE thread. Idempotent; a record already linked to another account is never re-pointed.
- **Platform threads** (`stitch.server.ts`): `mintStitchCode` / `stitchByCode` / `stitchByPhone` merge a handle thread into the phone-keyed one (adopt, else fold turns and leave a pointer), mark the context MOVED. A stitched phone stays unverified.
- **Phone mandatory.** An account created on or after `PHONE_MANDATORY_FROM` (`phone-required.server.ts`) can never skip the phone code (only a platform-wide send outage lifts it). `sms_runtime_config.phone_required` must be `true` in each environment (operator step).

## Operator steps
- Migration `20261112200000_prospect_spine.sql` rides each promote rung (single-file apply, never `db:push` to dev).
- `scripts/repair-prospect-threads.mts --project-ref <ref> [--apply]`: folds duplicate `sms_notice_*` threads per owner + phone and stamps managed-workspace owners' house-less threads. Dry run by default, JSON backup before any write.
- `scripts/backfill-staff-manager-role.mts --project-ref <ref> [--apply]`: gives PropLane seat holders the `manager` role row. Dry run by default.
