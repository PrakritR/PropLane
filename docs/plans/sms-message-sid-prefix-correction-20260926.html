Observed trigger

The first staging backfill wrote 207 original inbound logs and 204 outbound manager rows, but treated 187 matching manager mirrors as integrity mismatches because their mirror-write timestamps differ. A narrow timestamp exception accounted for 186. The remaining row has a 34-character Twilio Message SID beginning MM. Official Twilio Message API specifies ^(SM|MM)[0-9a-fA-F]{32}$. The original and mirror provider marker, content, wire pair, owner, role, work line and identity match; only the timestamp differs. Existing projection SQL and adapter code often check only SM.

Decision

Use one exact message-SID predicate for SM and MM. Preserve original event time and content. For the manager mirror, accept timestamp drift only when the original source, exact SID, and every other stored field match. Keep retained historical owner-conflict rows isolated. Apply a new additive SQL migration for already-applied database functions/triggers; never edit previously applied migration bytes. Include scope, ACL and full-body postflight, backup and rollback rehearsal.

Files and acceptance

  • Backfill helper, wrapper hash and fresh cursor pin; focused test for MM mirror with changed timestamp and failures for different SID, owner, body, work line and identity.
  • New additive SQL updates canonical projector and affected historical/intent functions and guards to recognize both prefixes. Historical alias promotion requires exact original source proof. No account or workspace inferred from the SID.
  • Runtime inbound adapter/notice matching and outbound inbox lookup accept both valid prefixes. No provider call or SMS send in tests.
  • DB negative probes show one MM original and mirror become one turn; replay is idempotent; provider collision and delete tombstone prevent resurrection. Staging backfill passes two clean inventories, then browser main and edge paths.
  • Independent review and normal ship gate before promotion. Production database operations require exact-target backups and the authorized scope.
