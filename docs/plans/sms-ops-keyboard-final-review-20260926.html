Actionable finding

R1 · P2 / Medium · Restoration's locked recheck does not protect every asserted prerequisite through commit

Locations: scripts/sms-production-visible-original-log-restore.mjs:81-91,116-136,181-203.

The apply transaction runs at the default isolation level and takes its own advisory lock. Its source query locks only i,b,r; the historical line count reads manager_sms_numbers and portal_workspaces without locking them. Alternative manager/relay transport absence and the matching-notice inventory are ordinary predicate reads. FOR SHARE protects existing selected notice rows, but cannot prevent a newly inserted match. Repeating these checks before commit reduces the window without closing it.

Concrete failure: after the final line-count/alternative-source check, another transaction can change the eligible line's owner/workspace or epoch, or insert an alternative transport row for a pinned SID, and commit before this runner commits. Neither the existing row locks nor the restoration-specific advisory lock conflicts with those writes. The 18 inserts can therefore commit despite a prerequisite becoming false. Reconnected postflight may detect the problem, but the restoration has already committed. This contradicts the operation's promise that changed historical context or a new alternative source aborts restoration.

Required correction: before the authoritative recheck, protect the historical line/workspace inputs and relevant absence/count predicates for the remainder of the transaction. Use a reviewed lock strategy that actually conflicts with ordinary writers, including relevant inserts, such as appropriately scoped table locks where necessary; an advisory lock used only by this script is insufficient. Acquire locks in a deterministic order with the existing timeout, then recheck, insert, verify and commit. Retain existing notice locks and the exact 18-SID restriction. Do not solve this by weakening postflight or allowing changed source sets.

Validation: add a root-owned two-connection rehearsal showing that a competing historical-line mutation and alternative-source insertion either wait until the restoration finishes or cause restoration to abort before its inserts commit. Also retain the existing-notice archive/delete race case. This review did not run a database concurrency reproduction.
