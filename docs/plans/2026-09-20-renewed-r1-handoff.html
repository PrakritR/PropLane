Decisions and product behavior

  • Manager rollback no-ops when an authoritative cache event has already removed the optimistic reply. It never restores aiDraft, queue, resolved identities, or other metadata. It restores preview, time, and unread only while those fields still carry this reply's optimistic values. It also preserves unread state when another message or optimistic operation remains.
  • Conversation ownership controls composer clearing, busy state, errors, toasts, and similar active-thread UI. Viewer ownership controls durable reconciliation of the original source row.
  • The recipient and thread identity come from the initiating conversation captured before the asynchronous delivery begins. Navigation cannot redirect the reply to the newly selected conversation.
  • AI queue advancement now represents an explicit approval action. approveActiveDraft supplies the exact approved draft snapshot to the reply path; an ordinary manual reply no longer implies approval of a pending AI draft. This is an intentional product behavior correction from the old behavior, which advanced any active draft after any accepted manager reply.
  • An approved draft with generatedAt is consumed by exact identity against current storage. If A remains active, it advances normally. If a newer B is active, B stays active, only a queued A is removed, and A is recorded in resolvedAiDraftIds once. Legacy drafts without an identity advance only on a conservative active-draft structural match.
