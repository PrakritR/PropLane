Finding

P2 - Use the original inbound timestamp for suppression eligibility. src/lib/agent/leasing-sms-agent.server.ts:437 treats prospectBurst.snapshotCutoff as the inbound timestamp. Its producer at src/lib/sms/prospect-sms-burst-job.server.ts:119 uses prospect_sms_ingress.received_at, which defaults to database insertion time (supabase/migrations/20260912143000_prospect_sms_bursts.sql:43). This can be later than the authenticated inbound event, particularly during slow intake or receipt recovery. Example: original acknowledgment at T0, outgoing message delivered at T1, recovered ingress inserted at T2. The new filter accepts T1 <= T2 even though the recipient could not have acknowledged that reply at T0. The worker already resolves authenticated original event timestamps into originals[].receivedAt. Also, leasing-sms-agent.server.ts:55 expressly permits every candidate when the inbound date is malformed, violating fail-closed ordering.

Correction plan

  1. Thread a dedicated trusted original inbound occurrence timestamp from the resolved receipt envelope to the SMS agent. Keep the existing history snapshot cutoff independent; changing its semantics could regress history fencing. For acknowledgment eligibility use the applicable original event timestamp, with conservative handling of a merged burst.
  2. Reject suppression eligibility when the timestamp is missing or invalid. Do not substitute worker-start time as proof of delivery-before-inbound.
  3. Add behavioral loader/agent tests for delivered before original inbound, delivered after original inbound but before ingress insertion, invalid timestamp, submitted/sent/failed/unknown delivery, and unknown reference ID. Exercise the real candidate-selection path rather than injecting an already-approved recentDeliveredReplies array.
  4. Add a model-facing harness that calls the actual listing tool and verifies its tool result reaches the next model request, for both prospect and verified resident scope. Use real nonproduction listing data for the required integration evidence and record its trace. Current loop regression stubs a correct final answer without calling the listing tool, so it proves error propagation but not capacity grounding.
  5. Test deferred publisher false/error outcomes through the inbound after callback, and stale/duplicate/recovery handling with the existing revision claim boundary. Then complete the repository release gates when resource headroom permits.
