Findings

R1 - P1: opening a named SMS-only row displays every SMS conversation

src/components/portal/resident-communication.tsx:624-629 mounts RoleSmsPanel without selected messages or a conversation key. role-sms-panel.tsx:105-112 renders the whole endpoint's flat messages feed. With manager A, manager B and unknown history, selecting B shows all three. The new list isolation is therefore lost in the actual thread. Archived SMS-only rows also open that same unscoped feed. Pass the selected proven messages to a scoped timeline, and give the unknown row only the remaining unknown messages.

R2 - P1: client folding discards exact bindings and contradicts conflict isolation

resident-communication.tsx:311-327 ignores existing smsConversationKey/smsBindingKeys, matches manager id without checking a nonempty conflicting stored email, and treats either missing property id as a wildcard. A row deliberately left unchanged by the server because its email conflicts is then renamed and folded into that manager's SMS history. A row explicitly bound to key A can fold into key B if B is the sole returned manager match. Preserve explicit bindings, reject conflicting identities, and require server-proven recovery instead of treating missing provenance as proof. Compare the existing manager caller in pro-unified-inbox.tsx:607-631.

R3 - P1: assistant isolation is undone by the outer list merge

resident-communication.tsx:314-327 excludes Assistant from SMS matching but still assigns its stored email as personKey. With SMS disabled and an Assistant row carrying the same email as a human row, mergeUnifiedInboxItems combines them. The new guard in portal-inbox-storage.ts:1130 cannot prevent this second merge. Assistant rows must never receive a human person key or binding.

R4 - P2: a read unknown SMS hides unread verified managers

resident-communication.tsx:421 returns an empty array when the unknown flat remainder is read on the Unread segment. This discards the already constructed verified array containing unread manager conversations. Return the verified rows when excluding the unknown item; test an unread known manager plus a read unknown message.

R5 - P2: Archive does nothing for the unknown SMS row

resident-communication.tsx:402-404,434-447,598 enables SMS Archive for every row and persists text-messages to the local archive set, but the unknown branch never reads that set and always returns no unknown messages in Archived. The row remains active and cannot be restored. Implement consistent viewer-scoped archive/restore for this fallback or do not expose its unsupported action.

R6 - P1: exported route helper violates the installed Next route entry contract

src/app/api/portal-inbox-threads/route.ts:47 exports enrichResidentManagerIdentities solely for its unit test. The installed node_modules/next/dist/build/webpack/plugins/next-types-plugin/index.js:45-67 generates a checkFields<Diff<...>> allowlist of HTTP methods and route configuration exports; arbitrary helper exports are not accepted. Move the helper to a server library and import it from both route and test. Build/typecheck was not run, so no runtime exit result is claimed for this finding.

R7 - P1 gate: targeted lint currently fails

The root validation coordinator independently reported ESLint exit 1, one error and 33 warnings, with a quiet single-file rerun also exit 1. resident-communication.tsx:208 fails react-hooks/preserve-manual-memoization because loadResidentSms uses setSmsConversations without the inferred dependency. Fix the dependency and rerun the same bounded lint check through the coordinator. This is supplied command evidence, not a reviewer-run check.

R8 - P2: merged archived email rows expose only one member's history

resident-communication.tsx:325-327,461-466,640 groups archived email rows by person and passes only the first email member id into the inner panel. portal-inbox-storage.ts:1138 deliberately keeps ordinary trash rows separate, and resident-inbox-panel.tsx:1196-1205 resolves just one of those rows. Supply the exact selected email members to a display-only merged timeline while preserving source ids and archive/read/reply authorization.
