P1: New publish gate rejects valid V2 short-stay prices

src/components/portal/listing-wizard-v2/listing-editor.tsx:3161 uses rooms.some(listingRoomHasRent). That helper accepts monthlyRent or explicit rentBasis daily/weekly fields. The active V2 pricing editor instead writes shortTermRent for nightly pricing and weeklyRentPrice for weekly pricing without changing rentBasis (listing-pricing-step.tsx:647, 650, 675, 678). A short-stay-only listing with a positive visible nightly price and zero monthly rent therefore fails Publish with “Add a rent before publishing.” Adding the requested nightly rent never clears the error. This blocking gate is new in this diff.

Required correction

  • Make V2 publish readiness resolve a rentable offering using the fields and offered lease terms actually edited by V2. Reuse an existing effective-pricing resolver if suitable. Include shortTermRent and weekly stay pricing, room defaults/inheritance, and supported term-specific monthly pricing. Preserve monthly and legacy explicit daily/weekly support. Do not blindly accept a price belonging only to a disabled lease term.
  • When no offered rent is populated, navigate to Pricing and focus a visible control that can satisfy the gate.
  • Add meaningful behavioral regression coverage for short-stay-only nightly and weekly V2 field shapes with monthlyRent zero, valid term-specific pricing where supported, and a truly unpriced listing remaining blocked. Prefer driving the actual V2 pricing controls for at least the nightly regression so the test cannot repeat the helper mismatch.
  • Keep ownership/server validation and whole-lifecycle serialization intact. No route refactor, schema change, or production data mutation is needed.
