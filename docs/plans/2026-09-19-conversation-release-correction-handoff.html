Corrections

  1. S1 resident relay ownership. fetchResidentSmsConversation now treats verified phone as routing data only.   2. S2 client provenance writes. Ordinary POST /api/portal-inbox-threads upserts remove client-supplied manager, property, counterparty-role, SMS-binding, and identity-provenance fields, including snake-case aliases. Existing rows restore their prior server-owned relationship values while ordinary mailbox and history fields remain editable. The shared record builder remains neutral so trusted inbound email, public contact, and admin server producers retain their server-stamped identity metadata.
  3. B35 resident Unread retention. A just-read selected row is retained only after it was admitted while unread in the same viewer, segment, read/all state, archive state, and search presentation. Retention requires the exact accepted member set, so a representative key may change but an email-only neighbor cannot inherit admission. Search, status, folder/segment, and viewer changes invalidate admission. A route already resolved in the prior presentation is cleared when excluded; a route that has never resolved may continue waiting.
