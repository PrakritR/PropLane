Execution contract

  1. Review both immutable SQL files and runner. A source hash change aborts before credential bootstrap. The target is fixed by name and exact project ref. Credential bootstrap verifies project-bound host/user, PostgreSQL identity/role and pinned TLS root.
  2. Read-only preflight requires the existing scheduled inbox table and expected columns, auth.users and UUID generation. It requires both ledger entries and every listed new table/index/RPC/guard/trigger to be absent. A partial or previously applied state stops the operation.
  3. Apply first creates a fresh mode-0600 custom pg_dump archive directly under /private/tmp. An existing path is refused. pg_restore --list must pass before the transaction starts. Preserve the private archive outside the repository.
  4. One transaction obtains a task advisory lock, sets 3-second DDL lock and 60-second statement timeouts, repeats all preconditions, runs the two SQL files in order, inserts the matching ledger rows and validates catalog state before commit. Postflight reconnects read-only and verifies both exact ledger hashes, four table RLS/ACLs, three indexes, five service-only RPC ACLs and the active UPDATE/DELETE guard trigger.
  5. If a command fails after commit was attempted, its generic failure output does not establish rollback. Run read-only postflight and inspect the exact ledger/catalog state before any retry. Never replay a partially applied state.

Release checks and material risks

Staging QA must verify reminder history and scheduled inbox behavior with nonexternal fixtures, then the full named migration parity gate and remaining SMS release gates must pass. Do not exercise provider sends on production merely to validate metadata. This operation does not backfill past reminders, repair data, send messages, alter the six-SMS manifest or promote branches.

The new scheduled trigger blocks edits/deletes of rows once sending starts. Existing cron/manual paths may resume delivery after the missing claim RPCs become available. DDL takes locks on the scheduled table; the 3-second lock timeout stops rather than waiting through sustained traffic. The backup archive's list check establishes archive readability, not a rehearsed restore.

Failure and recovery

Failure before commit rolls back both DDL and ledger entries. If commit acknowledgment is uncertain, reconnect read-only for the exact target and run postflight; a mismatch requires human review of the catalog and ledger before further writes. Keep the pre-apply backup. Do not automatically drop new tables or restore a full database after live delivery begins, because the new tables can contain duplicate-prevention state. Recovery then needs a reviewed, bounded plan.
