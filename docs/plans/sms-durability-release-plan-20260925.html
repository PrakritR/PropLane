Any failed or uncertain commit requires fresh postflight inspection; never assume rollback. Preserve the backup outside the repository.

Failure handling

A migration operation that fails after beginning its transaction must be treated as uncertain until the exact target's postflight is read. If the ledger is absent and the schema remains absent, inspect the preserved backup and retry from preflight. If the ledger is partial or the schema differs, stop and investigate; do not use supabase db push --include-all as a repair. If reconciliation is incomplete, keep cutover readiness false, preserve the cursor, resolve the source evidence, and rerun bounded passes. Do not push a site branch while its target database is incomplete.
