Evidence and limits

The execution manager reports baseline and three candidate full-E2E attempts stopping before browser cases, while separate build, lint and integration succeeded. This plan does not claim a proved kernel OOM. The repository's next.config.ts, lines 67-78, documents the known risk: Next's compiler parent and its large typecheck worker overlap their memory peaks. The existing build job already runs npm run typecheck as a separate required step, then builds with PROPLANE_TYPECHECK_SEPARATELY=1. Playwright currently starts npm run build && npm run start without that flag, repeating the combined compilation/typecheck path.

The proposed change eliminates this redundant in-build typecheck through the existing flag, and exposes build/start output for the next run. A successful new run establishes operational improvement; an early runner shutdown again requires diagnosis from its actual output, not repeated claims that memory is proven.

Why this dependency is acceptable

The old independence comment prevents a red or slow unit/integration result from hiding a compiler failure. This change preserves that objective: unit, integration, lint and build still run without dependencies on each other. Browsers receive a narrowly justified prerequisite: their compilation no longer repeats type validation because build already proved that same source SHA typechecks and compiles. No validation is waived. A separate typecheck inside each browser job would retain complete independence but duplicate the expensive check and consume timeout headroom; that is greater resource and timing scope for this release. A new standalone typecheck job would require another aggregate-gate change and is unnecessary.

The existing build job has conditional property-metadata preflight and legacy encrypted-QA-artifact steps. Their failures will also skip dependent browsers for those applicable dispatches. This is conservative and must be stated honestly; do not split or weaken those gates as part of this correction.
