Findings

P1: A ready-to-ready account switch retains the previous viewer's panel rows

src/components/portal/resident-inbox-panel.tsx:342-380, pro-inbox.tsx:412-445, and vendor-inbox-panel.tsx:222-250.

The effects assign the new panel viewer, but clear local rows only when readiness is false or the new viewer is null. With A already loaded, switch directly to ready B and defer or fail B's GET: A's local rows remain. The store's viewer-change purge does not emit an inbox-change event, so the new subscription does not clear this state either. Rejecting A's late completion is insufficient because A's already-published snapshot survives. Manager inboxSynced likewise remains true during a direct switch. Parent list readiness can hide some surfaces, but does not establish ownership for the retained child snapshot or its action/automation state.

Correction: bind published panel rows and readiness to viewer identity/generation, immediately make old-viewer presentation unavailable on every identity change, and hydrate only from a cache proven to belong to the intended viewer. Preserve failed-refresh rows only within the same viewer. Reset manager readiness on a new viewer, not only while signed out. Do not clear or write shared storage as part of this reset.

P1: Newly explicit writes can publish an old viewer's snapshot into the current viewer's cache

src/components/portal/pro-inbox.tsx:637-649,1818-1841; src/components/portal/vendor-inbox-panel.tsx:353-365.

New read-flag handlers capture previous, await an upsert, then restore the whole captured array on failure without checking viewer/generation. Start A's read, switch to B and load B's rows, then resolve A's POST as a failure: the rollback stages A's array into B's current cache and sets it as local state. stagePersistedInboxRows and upsertPersistedInboxRows use the current global viewer at call time; they do not enforce the initiating viewer. Manager AI draft completion similarly derives rows from localRef and now immediately upserts them with no initiating-viewer check after its awaited fetch. A delayed draft response can therefore write under B, especially while finding 1 leaves A's local array present.

Correction: capture an operation ownership token at initiation and reject success, error/rollback, cache writes and downstream upserts once viewer ownership, generation or mount changes, including A-B-A. Reconcile rollback against current authorized cache so a concurrent newer event or another mutation is not discarded by restoring an entire older array. Derive AI draft changes from the current authorized cache immediately before applying them. Check failed AI upsert outcomes instead of silently treating them as persisted. Existing resident rollback has the same ownership pattern; include it in the bounded correction for a consistent contract.

P2: Behavioral regression coverage omits the sibling hydration races and viewer-pending window

tests/unit/resident-inbox-hydration-read-only.test.tsx; tests/unit/manager-inbox-search.test.tsx; tests/unit/manager-inbox-ai-draft.test.tsx; tests/unit/cross-inbox-reply-integrity.test.tsx.

The new real-storage resident harness is valuable, but its A-B-A case immediately stages B and never checks that A disappears while B remains pending or fails. No equivalent manager/vendor real-storage hydration race tests are supplied, despite the sibling addendum. The changed sibling tests mostly adapt mocks and verify individual actions; they cannot expose a cache ownership failure. The AI test mock always reports successful upserts and cannot detect the failed/delayed write paths.

Correction: add focused behavioral tests for all three real panels: A disappears before B resolves and stays absent on B failure; null-to-intended viewer and A-B-A completions; cache event after accepted hydration; no ambient POST on mount, successful empty and failed reads. Add delayed failed read-flag and delayed AI draft cases across viewer changes, assert both cache and DOM ownership, and retain dedicated explicit-action assertions. Manager search still inherits the real status loader while mocking only its old array loader; align that harness to prevent incidental real fetch/session behavior from determining the result.
