P1 R4: Concurrent replay can pass the deletion tombstone check and resurrect a deleted event

supabase/migrations/20260925160000_sms_projection_corrections.sql:46; supabase/migrations/20260925160000_sms_projection_corrections.sql:173; supabase/migrations/20260925160000_sms_projection_corrections.sql:191; supabase/migrations/20260925170000_sms_projection_historical_identity.sql:120

Delete locks the summary, writes event tombstones and deletes the projection. Projector/importer check tombstones earlier, before their provider lock, and never recheck after it; delete does not take the provider lock. A valid interleaving is: replay observes no tombstone, delete commits, replay sees no old turn and inserts it again. The ordinary sequential replay probe does not establish the promised concurrent durability.

Required correction: Use a shared deterministic locking protocol for delete, live replay and historical import, and recheck tombstones under that lock immediately before insertion. Keep source-event tombstones exact and preserve other lines/roles. Add an additive migration only. Prove the paused replay/delete interleaving with two bounded database clients; do not weaken source immutability.

P1 R5: Historical replay and cutover verification still omit canonical identity checks

supabase/migrations/20260925160000_sms_projection_corrections.sql:195; scripts/backfill-sms-projection.mjs:121; scripts/backfill-sms-projection.mjs:196; scripts/backfill-sms-projection.mjs:360

The projector immediately accepts an existing historical provider SID after comparing body/direction and optional wire phones. It does not compare occurred_at, role, person identity or work-line epoch, and it never moves a synthetic import after new exact proof. Subsequent live SIDs can then create a different canonical conversation. Backfill loads only role and line from summaries and eventMatchesStored omits identity_kind/key/user, so it can call another person’s projection alreadyMapped and permit readiness. A direct Node 22.23.0 probe of that exported function returned true for the same source envelope with stored user:person-A and candidate user:person-B. This was a pure local check with no database mutation.

Required correction: Compare the complete original envelope and canonical identity during live historical replay and reconciliation. Distinguish legitimate proof-backed enrichment from conflicting attribution; move only individually proven originals and recompute summaries/aliases/state transactionally. Supply a bounded reconciliation path for existing synthetic imports. Mismatches must block readiness until repaired or explicitly retained as unresolved, never pass as already mapped.

P2 R7: Latest summary refresh overwrites the older-history continuation

src/components/portal/pro-unified-inbox.tsx:448; src/components/portal/pro-unified-inbox.tsx:476

The parent keeps already loaded older rows, but every first-page refresh unconditionally replaces smsNextCursor with that first page’s cursor. After loading page two, a poll or state refresh causes Load more to fetch page two again. Under ongoing refreshes users repeatedly traverse the same page rather than making reliable progress through old conversations.

Required correction: Store continuation for the oldest loaded summary page separately from the latest-page refresh result. Reset only on an actual scope/filter reset; append advances it and an exhausted cursor remains exhausted. Test page1 -> page2 -> refresh/new arrival -> page3, including an empty authorized page that has a continuation.
