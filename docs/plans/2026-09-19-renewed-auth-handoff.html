Diagnosis

The first read has two asynchronous boundaries: the SDK result enters readSession, then that helper's result enters refresh. The helper checks generation and lifecycle epoch. The outer continuation previously checked only lifecycle epoch. A concurrent refresh can resolve in the intervening microtask, observe a rotated identity, and increment generation without an auth callback. The older first-read snapshot then re-observes the previous token and clears the shared work map, allowing another explicit refresh.

The failing component fixture makes this possible because its refresh mock returns a rotated session without emitting TOKEN_REFRESHED, and its getSession mock always returns the original near-expiry session. That is not complete SDK renewal behavior. The implementation still needed the missing outer generation guard: the coordinator accepts injected dependencies and already guards generation changes independently of lifecycle events. Changing the fixture alone would leave that race untested.
