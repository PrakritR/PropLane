It accepts either explicit tour opt-in or a proven recipient-initiated inbound conversation for the exact manager, Twilio Messaging Service, prospect conversation key, transactional class, and lifecycle purpose. ## Design and safety decisions

- `resolveTourSmsEligibility` is the single positive lifecycle authorization decision.
- Consent lookups reuse `normalizeConsentPhone`; there is no second US-only key algorithm.
- Trusted positive sources are limited to `tour_inquiry_opt_in`, `recipient_initiated_inbound`, and `twilio_start`.
- A tour-purpose grant derived from recipient initiation rechecks the current manager-conversation event on every retry, so a later conversation revoke overrides the materialized grant.
- A newly created inquiry is stamped `smsOrigin: "leasing_sms"` only from the authenticated SMS runtime. Other creates are stamped `non_sms`; legacy missing origin remains compatible only when exact ledger evidence exists.
- Leasing SMS tools require the supplied phone to normalize to the authenticated sender. Channel is explicit across SMS, voice, and email agent contexts.
- Lifecycle tracing reuses fail-soft `traceSystemNotification`. Metadata/output contains manager id, inquiry id, lifecycle purpose, channel, SID/outbox status when returned, and enum-like outcomes. It contains no phone, email, body, or free-form provider error.
- Guest email replies reuse the pair-signed inbound-email token. Invalid, unconfigured, or tampered tokens retain the existing fail-closed/fallback behavior documented in `docs/agents/inbound-email-inbox.md`.
