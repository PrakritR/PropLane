Required contracts

  • Owner/tenant isolation, role isolation and work-line scope are explicit. Prospect and resident remain separate roles as the repository requires. The same number held by two workspaces is one conversation visible in both holding workspaces; workspace ID is an authorization/placement input, not an extra conversation fork.
  • Phone formatting, renamed contacts, assigned house labels, profile linkage, retries, burst boundaries and account switching cannot mint new identities. Distinct verified people who happen to share a phone must not be merged. Never infer a person from a name, message body, or unverified client-supplied account ID.
  • Use existing resolveCommunicationScope / conversationVisible, house membership and work-number ownership evidence for every list, detail, archive, delete and reply. A stored alias is not authorization.
  • Keep legacy conversation keys compatible for consent, agent sessions, outbox, conversation houses and send authorization. New opaque conversation IDs belong to the Communication projection. Resolve legacy keys through an explicit alias table rather than globally rewriting buildConversationKey.
  • Transport events use immutable provider ID, original body, original received time, From, To and direction. Agent prompts may concatenate these events but cannot overwrite or synthesize a provider message.
  • No production changes, release, real SMS, no-mistakes, Linear or Lavish. Preserve all unrelated dirty work. Read local Next guides before route/UI changes and the relevant UI/agent instructions before touching those areas.

Architecture decision

Implement one SMS Communication projection shared by both UI flag states. Keep current receipts, ingress and outbox as operational source evidence. Keep ordinary portal email/chat storage unchanged. The projection is an additive, replayable read model, not a second SMS sender or a replacement consent/agent framework.

The additive SMS projection addresses the observed pipeline mismatch while keeping existing operational stores and compatibility identifiers available for audit and rollback.
