Source execution handoff for the plan docs/plans/2026-09-19-resident-hydration-destructive-persistence-plan.html. Worktree: /Users/akhilvemuri/.treehouse/AXIS-2-ea44f0/9/AXIS-2. Starting HEAD supplied by the plan: 480929fa3.

Result: resident, manager, and vendor inbox hydration and cache observation no longer own a passive full-snapshot network writer. A server read, mount, viewer transition, or cache event cannot infer missing ids and call deleteIds. Explicit user and product mutations remain explicit writes.

Implementation decisions

  • Each inbox panel captures a hydration generation and intended session viewer. Accepted completions must still be mounted, belong to that generation and viewer, pass the shared initial-viewer observer, and match the authenticated cache viewer.
  • Hydration uses syncPersistedInboxFromServerWithStatus with the existing bounded stale retry. Failed, malformed, or stale reads preserve the usable presentation. A successful empty read is accepted as an empty presentation and remains read-only.
  • An accepted completion reads the current authorized cache after the loader commits instead of applying its captured response array. Scope-filtered cache events also verify viewer ownership before reading.
  • The resident parent no longer queues a captured full array to stage an Assistant placeholder. The existing pure pinned presentation helper supplies the placeholder without writing shared storage.
  • Manager and vendor read/unread actions now stage, upsert, and roll back explicitly. Manager AI-draft generation also upserts the changed row explicitly because it previously relied on the removed passive writer.
  • Archive, restore, permanent delete, accepted reply/compose, refused-send rollback, and source-aware read paths retain their dedicated mutation APIs.
