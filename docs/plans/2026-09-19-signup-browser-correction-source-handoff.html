Signup browser correction - source handoff

Source changes are limited to the three assigned browser specs and one signup fixture helper. No runtime, browser, server, database, build, test, graph, or Git command was run.

Changes

  • The signed-in Start free journey follows the current public CTA, checks the stable manager submit control and its signed-in label, confirms the phone field is required, and preserves the new-session email identity proof.
  • The two new-manager journeys now use the stable manager-trial-signup-submit control, require the phone field, observe the real manager-registration response before onboarding, and retain the real onboarding path.
  • Each generated manager identity is created before submission under an exact dev/test host and service-key gate. A finally block invokes the product's complete account purge for only that exact generated Auth user, including partial registration failures.
  • The signup fixture now intercepts only the exact owned manager-registration body and forwards its headers, cookies, and body through a fixture-owned standalone Playwright API request context to the same origin. That retained operation survives browser-context closure, remains alive through cleanup, and is disposed only after cleanup has drained it. Callers close their page or context before cleanup, and cleanup drains the forwarded request before any identity lookup or purge. A forwarding operation that is missing or ends with a transport timeout/failure leaves the generated identity untouched and fails with that owned email instead of racing cleanup against server provisioning.
  • Evidence JSON and console output no longer include generated passwords. The application journey no longer deletes a row by resident email before starting.
