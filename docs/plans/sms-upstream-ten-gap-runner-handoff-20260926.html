Inherited ten-gap migration runner

Production schema execution is not authorized. This handoff covers the reviewed runner and local focused tests only. Root owns backup creation, staging application, full release validation and any later production operation.

scripts/sms-upstream-ten-gap-migrations.mjs accepts only the exact staging and production project refs and the ten pinned SQL filenames, order and SHA-256 hashes from the operation plan. It defaults to read-only preflight. An apply requires --apply-authorized, a new target-named backup under the private release backup directory, a validated custom-format dump, and a single advisory-locked transaction. It checks the exact ledger and expected catalog before and after SQL, rolls back on a mismatch, and reconnects for postflight.

node scripts/sms-upstream-ten-gap-migrations.mjs --target staging --phase postflight

The apply command creates the backup with mode 0600, runs pg_restore --list, records its SHA-256, and prints only target, fingerprints, backup path and outcome. The destination file must not already exist. Replace <UTC> with a unique timestamp. An uncertain commit requires a read-only postflight inspection before retrying. A partly applied ledger or catalog is an investigation stop.
