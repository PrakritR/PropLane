Why this bridge is necessary

The incoming src/app/api/twilio/inbound/route.ts verifies the webhook and provider account, checks shielding, persists a sanitized envelope and schedules processAcceptedInbound. Its generic redactor is not a quote-proof storage policy: a 12-digit code must always be redacted, regardless of card-number detection. The old vendor route sees raw proof before ACK. Moving that call after ACK without a bridge either destroys the proof or stores it in plaintext. Challenge prebinding before ACK adds database lookup and policy failure dependencies to the acceptance deadline, so it is rejected for this integration.

The existing seven-argument consume_vendor_quote_sms_challenge commits grant, binding, event, original redacted log and completed owner receipt in one transaction. Its public overload fences canonical sender authority and the corrected directory-before-service lock order. Reuse it unchanged unless a concrete integration test establishes a missing guarantee. The new envelope layer is transport durability, never consent authority.

Add a server-only helper using Node's standard authenticated encryption, AES-256-GCM with a fresh cryptographically random 96-bit nonce and full authentication tag. Derive a fixed 256-bit key from the existing required service-role secret using HKDF-SHA-256 with explicit versioned quote-ingress purpose separation; use a different derived key for the quote wire digest. Do not introduce a new deployment credential. Never use the credential directly as an AES key, reuse nonces, log ciphertext/plaintext/keys or expose crypto errors. Version the format and reject unknown versions. Secret rotation makes old capsules unavailable; fail closed, do not attempt an unbounded key history.
  3. Bind the capsule to the accepted transport. Authenticate purpose/version, MessageSid, normalized signed From, original normalized To, exact AccountSid, runtime, provider MessagingServiceSid including absence, and the original-wire payload digest. Other messages retain their existing digest behavior. Key rotation may refuse an old duplicate; never weaken identity comparison to accept it. Keep the original raw request only in memory.

Extend EnvelopeInput with an optional typed quote capsule and persist it in a nullable, service-only envelope column, separate from provider params. Strip/overwrite reserved server keys for ordinary ingress too. No code appears in params, receipt, original log, projection, outbox, telemetry or response. Do not create a reply bubble for proof traffic.
  6. Pass an optional trusted processor context. Extend the envelope claim result and internal processor call with immutable persisted envelope identity, digest and optional capsule. The optional second processor argument is populated only from the claimed database row; preserve existing callers when absent. Validate capsule AAD against those row values and validate relevant params against them. Do not reconstruct trusted context from webhook-supplied params. Rate-limit this proof path separately after ACK; unavailable limit storage is a safe bounded retry, exhausted limit is a proof refusal.
  9. Keep the legacy endpoint compatible. /api/webhooks/twilio/sms already requires signature and processes proof before owner/agent lookup. Retry, ambiguity and cleanup

Quote consumption is a special safe replay because every grant effect is in the MessageSid-idempotent transaction. Keep its checkpoint safe while making only reads and this transaction. Do not mark a generic effect before it and strand a recoverable proof. Catch only this bounded proof path's known replay-safe failures as SafeSmsIngressRetry; never broaden the catch to arbitrary processor/agent/provider effects. Maintain the keeper's three-attempt limit, backoff and runtime/account isolation. Dependency failures must not be confused with an invalid proof or silently fall through.

Before a retry needs to decrypt an expired capsule, check for a previously committed exact proof outcome. A completed owner receipt must match MessageSid, signed original From/To, QUOTE [redacted], signedTwilio and workspace, and an actual consumed quote challenge with that SID and matching phone pair/capability workspace must support it. Unreadable evidence is retriable; conflicting evidence fails closed. This lookup is reconciliation of an existing committed grant only, never permission to create a new one, and must be scoped to the accepted envelope identity. It handles a response lost after COMMIT, process termination before checkpoint, and subsequent policy/STOP changes without replaying a grant.

On a committed or reconciled grant, record the existing delegated checkpoint using the same MessageSid, then return zero bubbles. The existing prepare/reconcile machinery can complete the envelope from the atomic completed receipt. A lost delegated checkpoint response must remain safe to reconcile. If there is no committed outcome and the capsule or challenge has expired, finish as a refused proof without consent or agent fallback. A malformed/tampered capsule is likewise terminal and code-free. Unknown ordinary-message effects remain frozen exactly as in the keeper.

Erase the sealed capsule after successful/refused terminal handling and expired-envelope recovery; clear expired capsules even on needs_review rows without changing their review status. Use the envelope lease/identity guard where a worker clears it. Keep the capsule's deadline independently queryable so the recovery cleanup can remove expired ciphertext without decrypting it. If cleanup fails, encryption and authenticated expiry still prevent reuse; retain a code-free operational reason. A replay after capsule removal must reconcile from the committed receipt or terminal envelope status. Do not persist a raw proof to make recovery easier.
