Private release CLI failure diagnostics handoff

This source-only change preserves both release transports and adds observability for a failed supported CLI invocation before any retry.

Failure evidence available after implementation began

Root's independent read-only PostgreSQL log review identified SQLSTATE 25P01 at 16:47:04.617: LOCK TABLE can only be used in transaction blocks, accompanied by three warnings for transaction-local SET statements. The pinned CLI transport did not provide the transaction that the guarded drivers assumed. The source guards failed before mutation, and the independent post-capture remained exact. This diagnostics change deliberately does not restore authored BEGIN/COMMIT, because doing so naively could separate the CLI migration-history write from the guarded DDL.

Implementation

  • scripts/release-conversation-schema-reconciliation.mjs now owns the shared private diagnostic writer and fail-closed throw helper.
  • Both the conversation reconciliation transport and scripts/release-resident-inbox-read.mjs call the shared helper for dry-run and apply failures.
  • The writer verifies the fixed PRIVATE_ROOT as a real 0700 directory, then performs one exclusive wx create with mode 0600 directly under that root.
  • The collision-resistant filename uses the phase, timestamp, process id, and 128 random bits. The artifact contains only the fixed project, phase, migration identity, capture time, status, signal, selected error metadata, stdout, and stderr. It does not serialize the environment.
  • The terminal error exposes only safe wording and the private artifact path. If artifact creation fails for any reason, the transport still throws with safe diagnostic-unavailable wording.
  • No retry, SQL fallback, migration repair, target change, source change, token change, lock change, transaction change, or direct apply entry point was added.

Focused coverage added

tests/unit/private-release-cli-failure-diagnostics.test.ts covers unique direct-root paths, 0700 root verification, exclusive 0600 writes, fixed artifact fields, absence of an environment dump, private output secrecy in thrown errors, failure remaining a failure, and fail-closed behavior when logging fails.

Validation status

No Node command, test, build, browser, server, database command, Git command, or graph command was run. The root owner explicitly retained those responsibilities because this laptop is constrained. This handoff reports source inspection only.

Required review before another CLI attempt

  1. Independently review the two transport call sites, the shared writer, and the focused test.
  2. Run the focused unit test under the repository's pinned runtime.
  3. Regenerate the sealed resident manifest and approval. The resident manifest pins both its runner and the shared helper digests, so every prior manifest is intentionally stale after this source change.
  4. Take a fresh independent capture and full backup, then confirm the original function and all 211 historical ledger rows remain exact before authorizing a new attempt.
  5. On any future CLI failure, inspect the named private artifact without copying its stdout or stderr into chat, console output, or repository files.
