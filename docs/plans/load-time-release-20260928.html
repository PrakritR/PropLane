Diagnosis

Static Next.js assets already used immutable CDN caching and returned cache hits. Authenticated HTML intentionally remains private. Inspection found avoidable client startup work, blocking native auth checks and repeated server/client reads; authoritative billing reconciliation also costs server time. PostHog identifies the slow routes but its historical Safari cohort does not identify native WebViews, so native attribution and causal speedup require the new runtime dimension and fresh production data.

What changed

  • Signed-out native sign-in waits at most 400 ms for its passive local session check. Its credential form stays available while a cached user is validated in the background. Active OAuth returns recover immediately on an already-visible mount; polling respects attempt limits, deadlines and cancellation.
  • Removed startup warming of ten unrelated panels and automatic portal-route prefetches. Desktop hover intent remains.
  • Moved the PDF filename utility into a lightweight module so client consumers do not import the PDF writer. PDF generation remains on its authenticated server path.
  • Coalesced redundant startup reads. Resident tour caching is keyed by viewer; writes invalidate it, and an older response cannot become fresh after invalidation. Resident application/service reads still refresh once per mount because the shared manager caches are not interchangeable with resident reads.
  • Manager billing reconciliation remains authoritative. Request-scoped reuse avoids repeated reconciliation and purchase-row reads; independent access/security reviews passed.
  • Production-only analytics correct original-navigation attribution and add browser timing breakdowns, a coarse native-runtime dimension and aggregate server reconciliation timing. Baseline queries use only proplane.ai and www.proplane.ai, excluding localhost, staging and previews.
