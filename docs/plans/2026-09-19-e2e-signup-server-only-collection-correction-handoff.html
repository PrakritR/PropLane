Source correction ready for root-owned validation. Full E2E collection previously loaded the product account-purge graph directly from tests/helpers/owned-manager-signup-e2e.ts. That graph reaches Next's server-only marker through the inbox scope and effective-session modules, so Playwright failed during collection before any signup case ran.

Correction

The browser helper no longer imports the product purge graph. Cleanup resolves the child entrypoint from Playwright's repository working directory and launches the pinned local tsx dependency in a short-lived Node child with the react-server condition. This avoids import.meta, which is incompatible with Playwright's CommonJS package transform. The condition applies only to that process; no global alias, test stub or server-only bypass was added. Execution is bounded to 120 seconds, a 512 MB old-space limit and a 1 MB output buffer, with no retry.

The child accepts exactly --user-id <uuid> --email <generated-email>. It refuses every Supabase target except the exact dev/test host, requires a service key, validates both the Auth UUID and the generated lowercase @test.proplane.local email shape, and re-reads Auth to prove that UUID and email identify the same user before mutation. It then calls the existing deletePortalAccountCompletely product cascade. Success requires an explicit Auth user_not_found result for that same UUID; a network or provider error cannot masquerade as absence. The parent also resolves the exact email before launch and proves it is absent afterward.

Child stderr and provider error messages stay captured and are not copied into test errors. Failures report only bounded process status plus the generated owned email so an unresolved test identity can be reconciled safely.

The two Playwright fixture continuation callbacks in tests/e2e/authenticated-test.ts were renamed so ESLint does not interpret use(...) as a React Hook.
