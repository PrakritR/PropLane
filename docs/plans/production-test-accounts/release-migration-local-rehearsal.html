Staging and production rehearsals passed on 2026-09-19. Both target-specific runs exited 0 and verified exact cleanup of the owned PostgreSQL process tree and private data directory. This harness is offline and disposable. It has no cloud connection, credential input, apply path, development server, browser, provider call, or customer-row restoration path.

node --max-old-space-size=256 scripts/testing/test-workspace-release-local-rehearsal.mjs

It requires Node 22, PostgreSQL 17 tools, a 256 MiB old-space cap, and the pre-existing bounded loopback cluster configuration.

Rehearsal order

  1. Restore the selected pinned schema/ACL, load both full catalog captures, and require their historical ledger and public-table inventory to agree. The restored local structural catalog must exactly equal the reviewed baseline catalog.
  2. Build and run the reviewed baseline bundle first: four immutable migrations for staging and five for production. The bundle is generated only after the local synthetic invitation preimage is captured. A copied local catalog carries that synthetic digest; actual target invitation rows are never restored.
  3. Refuse the recovery internal GUC, replica replication mode, a deliberately wrong synthetic invitation beforeimage, and an invitation that would receive an addProperties grant. Each refusal must leave the schema and historical ledger unchanged.
  4. Run the matching synthetic invitation preimage. Its digest must remain unchanged through baseline replay, and the exact historical ledger plus only the reviewed baseline entries must remain.
  5. Capture fresh local ledger and table inventory after the baseline bundle, then generate the immutable ten-migration feature bundle from that fresh local state. Existing attestation, ledger-drift, advisory-barrier rollback, exact-success, and role/RLS scenarios run only after this point.
  6. After success, prove only the target's historical automated_communication_reminder_kinds statement arrays: staging 20260916051253; production 20260915120000 and 20260916063005. The exported immutable COMPACT_STATEMENTS_SHA_SQL expression and PostgreSQL sha256(convert_to(array_to_json(statements)::text,'UTF8')) must each equal JavaScript sha256(JSON.stringify(statements)).

Containment and cleanup

The private cluster listens only on a dynamically allocated 127.0.0.1 port, disables Unix sockets, uses a random local SCRAM password, has bounded memory and worker settings, and strips inherited cloud connection settings from subprocesses. Cleanup verifies the random ownership marker, data directory, postmaster command and process tree before stopping only the owned server and removing only its private temporary directory. Failure output stays bounded and excludes historical SQL.

Limits

This local rehearsal cannot prove real target identity, backup recovery, cloud TLS, customer-data compatibility, application sessions, provider behavior, Storage HTTP, browser/native flows, or deployment results. Root-owned target verification, independent review, focused validation, staging QA, and release gates remain required.
