P1 F1: The first prospect text can fail before burst enqueue because projection timestamps disagree

src/lib/sms/inbound-pipeline.server.ts:172; src/lib/sms/inbound-pipeline.server.ts:739; src/lib/manager-sms-messages.server.ts:346; src/lib/claw-leasing-bot.server.ts:629; supabase/migrations/20260925150000_sms_projection_historical_import.sql:84

The inbound pipeline first projects the SID at sms_inbound_receipts.first_received_at. It then calls handleClawLeasingInbound without that original time. persistClawInboundSms logs the same SID with a fresh created_at; burst workers instead supply ingress.received_at. The RPC demands the exact prior occurred_at, so the second write conflicts even when its body is unchanged. logManagerSmsMessage now returns projection success rather than durable transport-log success. persistClawInboundSms therefore returns false and the leasing handler withholds its reply before enqueueProspectSmsBurst. A read-model failure also blocks legacy/shared-line paths whose line cannot resolve. A unique-insert race similarly keeps the losing writer timestamp instead of rereading the winning original.

Required correction: Choose one authoritative immutable envelope for every SID, hydrate it from receipt/ingress rather than caller processing time, and reuse it across all producers and retries. Keep operational-log success separate from projection status. Durable projection failure must enqueue repair without vetoing already durable transport or replaying paid work. Test the actual inbound pipeline through persistClawInboundSms, not isolated mocked logging.

P1 F2: Deleting one new line-scoped conversation can destroy another line's source history

src/app/api/manager/sms-conversations/route.ts:93; src/lib/manager-sms-messages.server.ts:156

Projection identity includes work_line_id, but DELETE delegates to the old owner + conversation_key deletion, which has no line predicate. The same owner/role/person on two work numbers has the same legacy key. Deleting one displayed projection removes operational rows for both lines, while deleting only one projected summary. Receipts, ingress, relay rows and pending repairs also survive, so retry/backfill can recreate the supposedly deleted conversation.

Required correction: Use an atomic projection-aware deletion/tombstone operation over exact authorized source-event membership. Preserve unrelated lines/roles/owners and operational evidence required by transport. Define permanent user-visible deletion versus retained operational receipts explicitly, and make projection replay/backfill honor deletion. Never route a projection ID through broad legacy-key hard deletion.

P1 F3: Backfill can fail or import the wrong source first

scripts/backfill-sms-projection.mjs:171; scripts/backfill-sms-projection.mjs:276; scripts/backfill-sms-projection.mjs:437; supabase/migrations/20260925150000_sms_projection_historical_import.sql:278

candidate.sourceId prefers message_sid, but the historical importer casts its source argument to the raw row UUID for inbound_sms_log and manager_sms_messages. A retired-line row with a normal SM SID therefore fails import. Bounded scans also advance to all later feeds even when the earlier ingress feed has hasMore=true; a later mirror can win before its authoritative original is scanned. eventMatchesStored ignores occurrence time and identity, while acknowledged mismatches are counted and skipped forever. loadWorkLine only matches manager_user_id, omitting the workspace-owner proof accepted by runtime and SQL; valid active lines can be imported under synthetic historical identity instead. The importer then refuses to move a proven historical event to live identity on replay, leaving a future live SID in a separate thread.

Required correction: Distinguish sourceRowId from providerEventId; enforce source precedence by exact evidence lookup independent of page ordering. Share owner/workspace/epoch resolution with runtime. Prefer canonical work-line import whenever proof exists; use isolated send-disabled fallback only for genuinely unresolved history. Add reviewed reconciliation for already imported synthetic events. Completion requires per-source accounting, original bytes/time/identity verification and rerun stability.

P1 F8: Unknown aliases collide, and account enrichment can move more history than its proof covers

src/lib/sms/project-manager-sms-event.server.ts:40; supabase/migrations/20260925150000_sms_projection_historical_import.sql:103; supabase/migrations/20260925150000_sms_projection_historical_import.sql:136; supabase/migrations/20260925150000_sms_projection_historical_import.sql:205

Unknown identities are intentionally per-SID, but all unknown messages from the same phone bind the same owner/role/line/legacy_key alias. The second unknown SID gets an alias collision and rolls back. During phone-to-user promotion, event_count==1 is enforced only when a target user summary already exists. Without a target, the entire phone summary, potentially many originals, changes to the user identity from proof of only one SID. With an existing target, the same multi-event summary cannot promote at all. Existing aliases can remain attached to merged placeholders; alias collision and redirect-chain behavior are not reconciled.

Required correction: Do not bind broad unknown-phone aliases as unique targets. Represent ambiguous lookup explicitly or leave it unresolved. Keep identity stable during linkage and require proof for every moved original; do not infer that all history sharing a phone belongs to a new account. Correct merge aliases/state atomically and test target-exists and target-absent cases with multiple events, concurrent promotion and recycled/shared phones.

P1 F9: Read acknowledgments can mark unseen new arrivals read, and bulk actions use the wrong state store

src/app/api/manager/sms-conversations/[id]/route.ts:53; src/components/portal/pro-sms-panel.tsx:470; src/hooks/use-unified-communication-bulk.ts:142; src/hooks/use-unified-communication-bulk.ts:274; src/components/portal/pro-sms-panel.tsx:400

Route all single/row/bulk state actions through one projection-aware API with CAS and partial-result handling. Import legacy read/archive state deliberately and derive row visibility from authoritative projection state.

P2 F11: The bounded summary reader still performs repeated full-directory scans and loses contact metadata

P2 F12: Projection recovery has acknowledged gaps and permanently stale queued payloads

src/lib/sms/inbound-pipeline.server.ts:172; src/lib/sms/sms-projection.server.ts:234; src/lib/sms/inbound-pipeline.server.ts:119

Required correction: Guarantee projection intent is durable with the receipt or reconcile missing projections from operational sources. Queue immutable source references and hydrate authoritative envelopes, or implement monotonic proof-backed payload upgrades. Classify permanent integrity conflicts separately with visible health counts; test receipt-read and queue-write failures, stale lease, corrected source and replay without provider/model calls.
