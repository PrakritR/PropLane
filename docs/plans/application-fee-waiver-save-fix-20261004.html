October 4, 2026. Local changes on agent/assistant-chrome-polish, starting HEAD 671dc20d3825ef2da013dcba5c1b8549ffbbddef. No deployment or production writes.

Problem and fix

The manager Applications settings promo-code field saved only on blur. It was absent from the settings save registry, so pressing Escape while editing could close the dialog without saving. A blur request was also not awaited by the close routine.

Pending code edits now retain their property target and participate in the shared flush. Closing and switching settings panes await the request. Failed saves keep the edit and dialog available for correction or retry. Concurrent blur/close calls share one request. Unchanged blur sends nothing. Codes remain scoped to one property, and the authenticated server route remains the authorization boundary.

Changes

  • src/components/portal/settings-module-page.tsx: track pending property/code pairs, drain and await saves, preserve failed drafts, register the save handle.
  • tests/unit/manager-application-promo-code-scope.test.tsx: focused Escape save, failed-save preservation and retry, in-flight close ordering, duplicate suppression, clearing and unchanged blur.
