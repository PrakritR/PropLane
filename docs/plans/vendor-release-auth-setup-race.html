Cause and selected correction

src/app/auth/choose-portal/page.tsx automatically calls its normal selection handler for a single reachable role and navigates using window.location.assign. The helper correctly waits for either the destination or an enabled role button, but its subsequent URL check and awaited click are separate operations. Navigation can happen between them. An unbounded locator click then waits for a button in a document that has been replaced.

  1. Preserve sign-in, chooser navigation, current role-specific accessible-name locator, and existing path-boundary destination matcher.
  2. Give the single role-option click an explicit 5000 ms maximum. This shortens one action timeout; do not increase the 60-second test deadline, chooser deadline, or final destination deadline.
  3. Await that click normally. Catch only a Playwright TimeoutError when the page is still open and its current pathname matches the existing requested-destination matcher. Rethrow the original error otherwise. Do not return while a click promise is still pending.
  4. After either successful click or narrowly accepted navigation race, execute the existing final destination assertion. A closed page, unrelated error, wrong portal, similar prefix without a path boundary, or a chooser that refused selection must fail.
  5. Keep the correction test-only. No application UI, auth API, cookie, seed, database, index, migration, CI timeout, retry, or test-selection changes.

Do not use Promise.race to leave a click running after success. Do not catch every error merely because a URL looks correct. Do not add a second click, an API/cookie bypass, a broad role fallback, force-click, test skip, or retry. A refused single-role auto-selection must still surface as failure.

Alternative considered: require multiple visible roles before allowing a manual click. That couples the helper more tightly to chooser internals and changes behavior after failed auto-selection. A bounded, settled action with strict destination evidence preserves the existing workflow with a smaller change. A simultaneous URL/click race requires cancellation guarantees the locator API does not provide.
