P2: an enabled Send discards the draft during transition

src/components/marketing/resident-lifecycle-prototypes.tsx:56, src/components/marketing/resident-lifecycle-manager.tsx:521 and :893.

Click Prepare reply, then Send within the 930 ms activity transition. Prepare immediately populates the draft and removes itself. Send remains enabled because it tests only whether the draft is empty. The new unconditional busy guard returns without adding the message; the manager submit handler nevertheless clears the draft. Once the timers finish, the guide says Send the reply, but Send is disabled and Prepare reply is gone. The visitor must invent another reply or restart the guide.

This is an integration regression: the original untracked prototype has if (busy && active?.target === target) return; the integration changed it to if (busy) return. Both versions need deliberate transition handling, but silent draft loss is introduced by this change. The existing test waits for each data-guide-active state before clicking, so it cannot expose the failure.

Bounded fix: pass transition state into the sample controls, disable controls that cannot accept an action, guard form submissions as well as pointer clicks, and clear local input only when the parent accepts the action. Cover the manager send race and phone signing state, where an ignored callback can similarly close the local signing preview.
