Retained original history is independent of processing completion

Root Astra plan addendum, 26 September 2026. Include with completed-receipt correction phase 2 after the independent phase-1 review. No implementation or database mutation is authorized by this document alone beyond the already requested SMS release scope and its review gates.

Evidence and issue

The read-only staging audit found two pre-recovery receipts in retryable state with NULL temporary payloads and retained resident inbound logs. They have no route, reply, lease or outbox state, and cannot be classified as synthetic fixtures. See the audit. Production has no noncompleted receipts. Deleting these originals, changing receipt status, inventing an envelope or granting permission to resume delivery would be wrong. Their retained original transport logs remain evidence of received texts regardless of the processing result. The current historical importer rejects them solely because the receipt is not completed, unnecessarily blocking global migration.

Bounded correction

Separate original-body proof from live processing eligibility. The service-only original resolver may resolve a NULL-payload receipt from one exact retained inbound log even when its status is processing or retryable, retaining all owner, SID, body, wire, sender-key, role, user and historic-line/ingress checks. A present malformed or conflicting payload still fails; no missing transcript fallback is introduced. Return the actual unchanged status and durable-log source.

The historical importer/backfill may use that proved retained original with the receipt’s exact original time. The runtime typed adapter must continue refusing noncompleted NULL-payload durable-log fallback; existing live retry and burst behavior must not gain permission to resume from these old logs. Receipt status, payload, delivery state, queues, provider and model work remain untouched by this historical repair. The 53 production receipts with no retained original remain outside the receipt feed, and the exact-18 production restoration remains separately bounded.

Acceptance

  • A processing/retryable receipt with NULL payload and one valid retained original imports exactly once and participates in both clean inventories without changing its receipt or sending anything.
  • The same receipt with no log, a mismatched log, malformed present payload, wrong owner/wire/key/role/person or unproved required line fails closed.
  • The live typed adapter rejects noncompleted durable-log fallback and makes no downstream projection/model/provider call; valid completed fallback remains accepted.
  • Real rollback-only PostgreSQL probes prove pending-log historical import, exact timestamps and unchanged processing state. Staging dry run and actual two-clean-pass reconciliation must account for the two retained originals.

This is a source-proof correction, not a general recovery operation for pending messages. Bundle it with the concrete independent review findings in the final correction plan, then use a fresh Sol-medium implementation session and fresh Astra review. Six already-applied migrations remain immutable.
