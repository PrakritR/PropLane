3. Routing and compatibility design

One all-surface policy, explicit rollback

Extend the existing model module rather than introducing independent provider choices at every route. Add a server-only master flag AXIS_AI_LUNA_ENABLED with explicit precedence: true selects exact gpt-6-luna on every supported runtime surface; false forces legacy routing everywhere, overriding old portal/SMS flags; unset preserves baseline behavior. Malformed explicit values must not be treated as true. Keep the old portal/SMS rollout knobs for backward compatibility when the master flag is unset. Production activation sets master true plus portal and SMS enabled/100 explicitly; rollback sets master false plus both percentages 0. Test all precedence combinations.

Use one typed selection helper accepting the surface/task, server-owned actor key where needed, legacy selection, complexity and request limits. Return the full AgentModelSelection, never only a model string. Keep TIER_MODELS as legacy models; replacing their strings with Luna would route an OpenAI model into the Anthropic API at existing sites. Explicit all-on mode must not quietly fall back on missing OpenAI credentials: use the existing controlled unavailable/fallback-copy path for that surface and flag misconfiguration in preflight. Outside explicit all-on mode preserve established missing-key fallback behavior.

Selection and credential checks must agree and happen before paid work, while existing confirmation/precomputed branches remain usable without a provider key. Detect and resolve conflicting AXIS_AGENT_MODEL* overrides in release configuration; a hidden Claude vision/global override must not defeat the declared all-on state. Any retained override applies only in legacy mode. Do not accept a provider/model from user input.

Shared completion for direct callers

Route direct SDK consumers through completeAgentModel or a thin shared task helper wrapping that boundary. The helper should select the model, check its credential, preserve surface limits and return the existing normalized content/usage shape. Reuse trace observers where present and add appropriate generation evidence to currently untraced paid paths. Avoid copying usage extraction into every caller. Keep deterministic parsing and fallbacks in each domain.

Add an optional provider-neutral named tool choice to the shared request. Map it exactly to Anthropic's named tool and Responses' named function selection. Housing-search and both import interpreters must receive the required function output, reject missing/wrong/duplicate or malformed output as their validators require, and never turn extraction into a side effect. Preserve tool schemas; do not enable strict schema mode globally without proving compatibility with existing optional/union schemas.

Vision and PDF conversion is required

The baseline OpenAI adapter currently flattens non-string content to text and therefore drops image/PDF blocks. Before unpinning vision, convert validated base64 images to Responses input_image data URLs and validated PDF blocks to input_file with appropriate filename and file data. Preserve block order and text, mixed text/tool-result turns, and opaque continuation output. Reject unsupported blocks explicitly rather than silently dropping them. Keep existing combined attachment counts, MIME/byte validation, private-storage scope and source references. Never fetch arbitrary new URLs merely to satisfy a model.

Root is verifying the official Responses/file contract. Complete a small synthetic image and PDF acceptance call with exact Luna and validate extracted known facts. If a modality is unsupported, return a precise capability finding to the orchestrator and preserve the working specialized path; do not pretend that it migrated or lose attachments.

Budgets, cache, costs and retry

Port the prior SMS 40,000 ms whole-loop model budget and 8,000 output-token ceiling deliberately; keep voice deadlines within its actual webhook limits and keep long import extraction ceilings around their current 16,000-token needs. Low reasoning is default for SMS and utilities; portal analytical routing may retain high. Tiny legacy 400-700 token output caps must account for reasoning tokens or outputs may become incomplete: choose bounded task caps validated by canaries, then retain short-text/JSON validators. No endless retries or automatic high-tier escalation.

Preserve baseline fetchWithTransient429Retry: at most one transient 429 retry, respect Retry-After inside the original deadline, no retry for insufficient quota. Integrate SMS deadlines and any abort signal without resetting the budget. Never replay a whole agent turn after tools may have performed inline actions. Incomplete, refusal, empty, malformed and missing-usage responses remain failures, with available usage retained.

Port the reviewed Luna explicit stable developer-prefix caching and 30-minute implicit caching only after root confirms current API compatibility. Continuations replay one developer prefix and all opaque prior outputs (including encrypted reasoning), not repeated prompts. Unknown usage/cost must remain unknown. Trace actual returned model/provider, cache usage, latency and failed-call-only costs; preserve actor/session/prompt/proposal trace metadata and no Langfuse initialization under tests.
