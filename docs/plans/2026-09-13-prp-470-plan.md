It is unsuitable for readiness: it waits on unrelated data and treats failure as settlement. Do not add a broad prefetch or duplicate raw API request to detect completion.

## Proposed implementation

Retain existing client stores and add explicit successful-read/error state. Share a small initial-list gate/hook and loading/error presentation between manager/resident. Preserve existing array-returning sync APIs for other consumers. Prefer store-owned read-state snapshots keyed by exact request scope; alternatively use one typed internal sync result with compatible legacy wrappers. Do not create two network/data paths.

Represent idle/loading/ready/error (or equivalent), viewer/generation, and retryable versus auth error. Successful empty and unchanged results become ready. Session/local placeholder hydration does not. A same-viewer successful in-memory snapshot inside existing TTL can satisfy repeat mount without skeleton; sessionStorage alone cannot prove successful current initial load. After first success, background requests preserve rows; error must not replace a usable list with skeleton.

Manager readiness aggregates resolved non-null viewer, inbox success, application-directory success, and SMS success when enabled. Trigger/join existing unforced applications sync with managerUserId. Rebuild filterContacts from the successful directory and expose its readiness/error/retry to ManagerUnifiedInbox. Ensure the render becoming ready sees final inbox AND directory snapshots, not a readiness boolean one render before the contact event lands. Investigate delayed relationship/vendor metadata only if a selected filter makes it affect membership; do not block the unfiltered list on irrelevant metadata.

Resident readiness aggregates viewer, inbox, and enabled SMS only. Keep optional manager-contact lookup independent. SSR and first client render show matching skeleton state, without reading browser cache in state initializers.

Capture viewer, cache key, and monotonic identity generation at inbox request start. Check after fetch/body parse and before auth-latch updates, cache commits, TTL/events, or returning publishable results. Finally removes only the captured slot still owned by that exact promise. Clear readiness on identity changes. Hooks must reject stale completion and derive visible state from matching viewer so old rows/selection cannot remain for one paint. Test A -> B -> A, not just string equality.

Initial retryable failure renders `Could not load conversations.` and one retry Button with promise-returning onClick. Authorization refusal respects existing session/access behavior without an automatic retry loop. Error must not masquerade as an empty inbox. If force is required for retry, use `createCoalescedRefresher`, scoped by viewer + portal/request options; do not force every mount or bypass in-flight guards. Preserve mutation exclusions and trash/restore merge behavior.

Inside the existing `data-communication-inbox-list`, render noninteractive conversation-shaped skeletons, aria-busy, and one status label `Loading conversations…`. Hide provisional counts, empty/add-row choices, selectable bulk rows, and desktop auto-selection until ready. Keep deep-linked thread IDs pending and never select a different thread as fallback. Segment/search changes after readiness use the loaded list without initial skeleton restart. Mobile remains list-first absent an explicit thread URL. Use existing tokens and reduced-motion-safe styling.
