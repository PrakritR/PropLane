Waiver save and display follow-up

Dedicated follow-up to production commit 4796d559d. The manager account/property was requested but has not been identified; this report distinguishes reproduced defects from verification of that specific account.

Reproduced defects

The automation dialog retained “Saved” after a new focused edit that had not been sent. Regression tests also reproduced an older settings read replacing a confirmed new code, no normalization of the displayed saved value, and successful HTTP responses being accepted without checking persistence. The application form editor silently discarded an enabled promo code when its separate fee override was off.

Fix

Waiver edits clear the previous success mark and autosave after a 600 ms pause, while blur/close still flush and await the same request. Success requires the PATCH returned code and a fresh property-scoped GET to match the requested normalized code. The displayed field uses the confirmed stored value. Failed confirmation retains the draft, reports failure and blocks close. Scoped load IDs and per-property edit revisions prevent stale responses replacing newer edits or another property's code. Form promo codes persist independently of the fee toggle. No authorization, schema, dependency or environment changes.

Validation

79 focused tests across seven files passed with one worker. The new property-switch regression covers a save on A completing while B's current read is pending. Security and Bugbot reviews are clear after resolving that race. Changed settings component and tests lint passed; the application editor retains exactly its two pre-existing lint errors and three warnings, with no new errors. Build and integration passed on the core-fix commit 656c3cce0; full units remain running. Whole-project lint has the same 10 baseline errors and 962 warnings. A separately dispatched property-metadata browser check passed three cases and timed out during workspace-selection cleanup in one unrelated case; it is not reported as green.

Dev/test browser reproduced stale “Saved” and verified paused input saving without blur: fresh server read and field both showed the normalized code before success. The form editor saved QA-TEMPLATE1004 with its fee override off, a direct dev/test database read confirmed it, and reopening Setup displayed it. Mobile (390 × 844) confirmed normalized paused-input save; invalid input retained the draft with an error; a mocked 200 write that did not persist failed confirmation; removing the mock and retrying saved and displayed the intended code; clearing produced a null stored code and empty field. Temporary codes and form data were restored from the pre-QA fixture backup. No production data changed. Native uses the same shared settings implementation; no routing or shell changes.

Scope and release

Only three components and two regression test files change. The third component keeps the promo input editable during an in-flight save; the save loop confirms the newest edit before success. The original workspace and unrelated work are preserved. No production database writes or migrations. Task-only Turbopack root configuration is excluded from release and will be restored after local QA. Local smoke is running with one worker and zero retries. The existing Apple missing/expired agreement blocker remains outside this fix. Deployment pending.
