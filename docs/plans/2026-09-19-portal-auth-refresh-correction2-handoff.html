Correction design

  • The coordinator now keeps two distinct ownership dimensions. Session generation tracks the active session identity and may be adopted by another concurrent read of that exact identity. Lifecycle epoch advances only for an auth lifecycle observation or explicit component invalidation.
  • The subscription's INITIAL_SESSION callback establishes current identity without advancing the lifecycle epoch. It is an observation rather than a transition, so it does not suppress legitimate near-expiry mount work.
  • Every invocation captures its lifecycle epoch before the first read. A successful response may cross a generation established by harmless concurrent observation, but it can never cross an auth event or component disposal, even when the final identity returns to the same A token.
  • The first-read and second-read outer continuations check lifecycle ownership immediately after their helper awaits. This closes the microtask boundary where an auth event can occur after the helper's final check and before the caller resumes.
  • The explicit refresh continuation checks full ownership before inspecting the SDK result. The outer coalesced-work continuation also checks the lifecycle epoch before returning.
  • Lifecycle invalidation clears the in-flight lookup. An older invocation's finally still removes an entry only when the map holds its exact promise, so it cannot delete newer work for the same identity.
  • The non-destructive application adapter, guarded permanent cleanup, synchronous auth subscription, disposed native callback, and late native listener removal from the prior correction remain intact.
