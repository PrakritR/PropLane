Implemented behavior

  • Native auth: passive native session detection is a bounded 400 ms getSession check. A signed-out user or failed lookup reaches the credential form promptly. Active OAuth recovery retains bounded polling, now honors attempt and wall-clock limits, clamps each call and delay to the remaining budget, supports cancellation, and removes abort listeners after settlement.
  • Portal startup: removed the role-unscoped ten-panel warm queue and immediate marketing-home prefetch from every portal layout. Automatic route prefetch is disabled while desktop hover intent prefetch remains available in production.
  • Refresh work: manager account-link and onboarding reads no longer force duplicate portfolio refreshes. Resident application mount sync runs once without bypassing the cache. Post-write forced paths remain.
  • Resident data: tour reads are keyed by user id and normalized email, coalesce concurrent requests, keep a 15-second successful-read TTL, do not cache malformed/error responses, clear old-viewer display immediately, and force refresh after successful scheduling/cancellation. Application, lease, and tour-link access reads now run in parallel. The already-authorized application result supplies the manager id, removing two later profile/application reads.
  • PDF bundle boundary: the client Applications panel now imports a pure filename helper rather than the top-level pdf-lib implementation. PDF generation remains in the authenticated server route and loads only when a PDF is requested.
  • Manager entitlements: provider reconciliation remains authoritative on ordinary reads and write/API gates. Request-scoped caching prevents duplicate reconciliation and duplicate purchase-row reads. Reconciliation now happens before the displayed purchase snapshot is cached, preventing a stale same-render display. A production-only aggregate manager_entitlement_sync_completed timing event uses a constant distinct id and carries only duration.
  • Browser telemetry: PostHog initializes on known production web/native hosts and excludes localhost, staging, and previews. The existing single $web_vitals event is attributed to its sanitized metric navigation URL in both $current_url and $pathname, with a coarse web/native runtime. A lightweight initial-navigation timing event waits until load settles, uses the original navigation entry URL, omits zero fields, and removes listeners/timers.

Safety decisions

The implementation deliberately did not move Stripe or RevenueCat reconciliation out of the render path. The same resolver controls displayed plan state, co-manager behavior, immediate expiry/revocation, and sensitive API authorization. A separately maintained snapshot was not proven safe within this change. Provider latency therefore remains, but duplicate same-request work is removed and aggregate timing is now observable without user/account properties.

Analytics sanitization strips queries and token-bearing path segments. Runtime metadata is a coarse enum. No email, phone, secret, document body, raw sensitive URL, billing identifier, or account id is added to telemetry.
