P2: Refresh can leave an unreachable gap in SMS history and conversation lists

src/components/portal/pro-sms-panel.tsx:565 and src/components/portal/pro-resident-detail-inbox.tsx:330 merge the newest 50-turn page with prior loaded turns while always preserving the previous oldest cursor, including null. They never establish that the refreshed head overlaps the existing window.

Exact history counterexample: initially the conversation contains turns 1 through 50, all loaded, with nextCursor null. Leave the tab hidden while turns 51 through 101 arrive. On refresh the endpoint correctly returns turns 52 through 101 and a cursor before 52. The client keeps turns 1 through 50 plus 52 through 101, discards the new cursor, and keeps null. Turn 51 is absent and no Load earlier control appears. With an existing non-null old cursor, earlier paging still starts before the old boundary, so it cannot retrieve the intervening gap either. A standalone Node arithmetic reproduction of this exact merge returned storedTurns 101, visibleTurns 100, missing [51], preservedCursor null, exit 0.

Exact list counterexample: initially 40 conversations numbered 1 through 40 are fully loaded with nextCursor null. While polling is paused, 41 newer conversations numbered 41 through 81 are created. The head returns 42 through 81 with a continuation cursor. src/components/portal/pro-unified-inbox.tsx:490 does not accept that cursor once its prior first-page IDs exist; it merges the new rows with the old 40 and retains null. Conversation 41 is unreachable until the list is reset. src/components/portal/pro-sms-panel.tsx:342 has the same issue on quiet refresh by preserving current.nextCursor. Keeping old rows prevents displacement loss for smaller changes, but does not bridge a wholly new head page.

Required correction: preserve the oldest cursor only when continuity between the refreshed head and loaded window is established. The safest bounded correction is to reset to the fresh authorized head and its fresh cursor whenever overlap is absent. This deliberately unloads previously loaded pages, but makes every omitted item reachable again and keeps request volume bounded. Alternatively, retain the old window and page from the fresh head cursor until an overlap is found, with cancellation, authorization checks, bounded work and an explicit retryable continuation. Do not blindly preserve the old cursor or mark the missing range loaded. Use stable IDs and timestamp/ID ordering; cover the fully exhausted null-cursor case.

Focused verification: reproduce both exact fixtures above for both transcript surfaces and both list surfaces. Assert missing turn 51 and conversation 41 become reachable through the new continuation. Include normal overlapping refresh preserving loaded pages, same-timestamp ID ties, and a viewer/workspace change while refresh is pending. No transport rewrite or database migration is needed.
