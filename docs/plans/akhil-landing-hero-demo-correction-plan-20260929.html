Problem

The parent ignores every action during a 930 ms transition, but enabled child controls mutate local state before learning whether the action was accepted. A rapid Send clears its draft without sending; a rapid resident signature can hide its preview without signing.

Implementation

  1. Make transition acceptance explicit between resident-lifecycle-prototypes.tsx and manager/phone children. Pass busy or an equivalent action-availability prop and expose an acceptance result if local cleanup depends on the callback.
  2. Disable action controls while their callback cannot be accepted. Guard submit handlers too, so pressing Enter cannot clear a rejected draft. Do not clear text or close the signing preview for an ignored action. Keep normal free exploration and replay behavior unchanged.
  3. Keep duplicate-action suppression, phase timers, and replay cancellation coherent. Avoid fixing only Send while leaving the same new busy guard able to discard another child's local state.
  4. Add a focused browser regression beside the existing guided test. Do not broaden into portal redesign, backend changes, source-prototype cleanup, or a whole-project testing campaign.

Exact acceptance and browser verification

  1. Load the homepage and locate the manager sample composer. Click Prepare reply. Before its transition finishes, attempt a native Send click and Enter/form submission. The prepared text must remain intact while busy, no message may be silently lost, and the sample must not advance twice.
  2. After the transition, submit once. Assert exactly one matching manager reply in the manager conversation and corresponding phone message, then verify the guide advances to the offered tour. Complete all remaining steps and replay successfully.
  3. Advance to Open lease. Immediately attempt Sign sample lease before the open transition finishes. The preview must remain available until signing can be accepted. Then sign once, observe Manager signature pending, countersign, and submit the service request.
  4. Restart during an active transition. Wait beyond the combined timers and verify the initial Prepare reply step remains selected, the initial conversation is restored, and no stale timer advances the reset guide.
  5. Run the focused homepage Playwright suite with one worker under Node 22, plus focused ESLint and diff check. Use the existing active test server only with its owner's coordination; otherwise pin and start one task-owned server after checking resource headroom. Stop it after active review.
