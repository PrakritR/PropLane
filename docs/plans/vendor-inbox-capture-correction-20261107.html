The shared sender only checks request-local SMS test capture, then calls Resend directly. An ordinary browser request has no SMS test context, so a durably classified test-workspace manager can reach the real email provider. A synthetic recipient address is not an external-effect boundary.

Decision and bounded implementation

Reuse the existing durable capture helper inside the shared conversation sender. This is the smallest change that covers both single and batch conversation email while preserving normal transport and quote behavior. Extending postResendEmail to batches would widen the change and require response-shape and payload-type changes. A quote-route-only guard would leave other callers of the same provider boundary exposed.

  1. In src/lib/portal-email-send.server.ts, import captureTestWorkspaceEffectForUser. Keep zero recipients a no-op and preserve the single-recipient-only contract when authorizeDelivery exists.
  2. Preserve the existing authorization check before any capture, and keep request-local SMS capture first with ID in_app_test. After that branch, before requiring a provider key or building/sending a provider request, await durable capture with userId: opts.senderUserId, kind: "email", the existing safe subject/fallback summary, and recipient count metadata.
  3. On durable capture success, return every recipient as { sent: true, resendId: "test_workspace_captured" }. Do not call Resend, require a provider credential, mint fake transport IDs, or introduce a new capture store. The existing helper must retain evidence before success.
  4. On classification, service-client construction, or audit failure, return the initialized unsent results. Never continue into the provider branch and never report capture success without evidence. Preserve this function's documented non-throwing contract.
  5. On normal classification, continue the existing single/batch implementation, including personalized payloads, 100-recipient chunks, sender identity, signed Reply-To, conversation headers, and per-chunk failures. Keep the existing second authorization check immediately before raw fetch after the new await. Do not move or weaken either quote authorization check.
  6. Document this boundary in docs/agents/test-workspaces.md with one concise invariant and relevant tests. No UI copy or transport API change is required.

The capture actor is a trusted server argument, not a new request field. The route already passes the authenticated user.id; body IDs, recipient identity, selected workspace, sender From address, and recordRef must not influence classification. Existing callers outside this route retain their trusted sender contract. Do not broaden supported test-workspace roles to vendor: manager, co_manager, and resident are the existing membership roles.
