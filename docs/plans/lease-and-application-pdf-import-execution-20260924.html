What changed

Source and extraction

Private PDF bytes are parsed server-side with source SHA-256, page spans, fillable fields, issue coverage, and bounded local OCR for up to four scanned pages. Disguised or active-content PDFs are rejected.

Application templates

Import creates an unpublished, editable draft. Managers compare the original with a full applicant wizard preview of unsaved changes, resolve issues, and publish a version. In-progress applicants pin their published version. Imported nonidentity questions preserve source order as custom fields; typed placement and consent fields remain canonical.

Lease templates

Managers can choose reviewed converted HTML or the legacy original PDF. A converted property template becomes the placement artifact with a separate PropLane Terms Rider. Source clauses remain in the base document. Manager confirmation compares the source PDF with the final artifact, acknowledges rider conflicts, and persists a server-issued source/final-HTML receipt. Send rechecks both hashes.

Open acceptance and operational risks

  • OCR is bounded to four image-only pages per PDF. Larger scans remain unresolved and cannot auto-publish. A clean one-page scan fixture passed; multi-page and poor-quality scans need live QA.
  • A complete typecheck and build were not obtained on this 8 GB laptop. Do not treat focused tests as a release gate.
  • End-to-end browser proof of import, issue resolution, publish, applicant completion, final lease comparison, and signature is still required. The dev/test seed path without Stripe succeeds; the full test seed needs a valid Stripe test credential.
  • Source order is preserved for imported custom prompts in the Additional details step. Structural built-ins stay in their required steps; their position can differ from the PDF and is surfaced as an import issue.
  • Import lifecycle analytics are limited to coarse IDs, modes, and reason codes. Additional funnel instrumentation can follow acceptance QA without exposing document text.
