## Description

Filed while tiering the UI docs ([PRP-183](https://linear.app/axishousing/issue/PRP-183/eight-overlapping-ui-docs-two-of-them-finished-trackers-that-still)). `docs/website-ui-audit-2026-08.md` looked like a dated snapshot to archive — it is not. **None of its findings are marked done**, and several are real accessibility defects. Archiving it would have buried them, so it stays put and its contents are tracked here.

Overall score in the doc: **13 / 20** — "acceptable foundation with significant cross-cutting redesign work required."

## P1 — accessibility and task completion

1. **Nested interactive controls on high-frequency pages.** Tours, resident dashboard, and property detail (room/bathroom controls) have clickable parents with interactive descendants — invalid focus and activation behaviour for keyboard and assistive tech.
2. **Contrast below target.** The public home page produced **14 colour-contrast failures**, sign-in **5**. Blue Steel decorative layers cannot substitute for the legibility wash at the final rendered state.
3. **Responsive nav shrinks to ~8px. **`DestinationNav` in dense equal-row mode avoids overflow by shrinking operational labels — trading an overflow bug for a readability and tap-confidence one.
4. **Scroll regions without a keyboard entry point** on representative public and detail pages.

## P2 — hierarchy and information architecture

 5. List-page chrome dominates records (title actions → destination band → search → filters → *then* content).
 6. Header actions lack priority — Applications exposes Filter/Edit/Send/Settings/Screening/Add as peers; same on Tours and Properties.
 7. Routed status navigation is oversized — Pending/Upcoming/Past render as three large CTA zones rather than compact tabs.
 8. Detail pages stack navigation layers — property detail can show portal nav + detail tabs + anchor nav, ~220px before content on mobile.
 9. Long detail records need progressive disclosure (resident detail is one uninterrupted stream).
10. Loading states discard structure — skeletons should preserve title, controls, column rhythm, row density.
11. `/admin/communication/schedule` **soft-404s** — renders not-found with **HTTP 200** while `/admin/communication/inbox/schedule` is canonical. Route registries, nav generation, and not-found status handling need reconciling.

## Suggested sequencing

**11 first** — a 200 on a not-found page is a correctness bug, not a design one, and it lies to crawlers and monitoring. Then **2** (contrast is measurable, testable, and a legal exposure), then **1** and **4** (keyboard/AT correctness). The P2 set is a coherent redesign pass and should be planned as one, not picked off.

Each finding should become its own ticket as it is picked up; this is the tracking parent. Related: [PRP-183](https://linear.app/axishousing/issue/PRP-183/eight-overlapping-ui-docs-two-of-them-finished-trackers-that-still).
