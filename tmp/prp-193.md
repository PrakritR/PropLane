## Description

The structural problem behind [PRP-186](https://linear.app/axishousing/issue/PRP-186/manager-signup-collects-no-phone-number-on-the-hub-path-only-the) and [PRP-187](https://linear.app/axishousing/issue/PRP-187/manager-signup-hangs-on-andquotcreatingandquot-forever-even-though-the), filed separately because fixing either symptom leaves this in place.

## Two doors

`create-account-router.tsx` branches on `?role=manager`:

|  | `?role=manager` | bare `/auth/create-account` |
| -- | -- | -- |
| Component | `ManagerTrialSignupForm` | `PortalAuthForm` (hub) |
| Fields | name, email, **phone (required)**, password | name, email, password |
| API | `/api/auth/manager-register` | `/api/auth/signup` |
| Role | manager, immediately | **none** — chosen later at `/auth/get-started` |
| Plan / trial | tier-aware, starts the 14-day trial | not involved |
| Copy | "Create property account", "14-day free trial · no card required" | "Create account" |

Both are reachable, both produce a manager, and **which one a person hits is decided by whether they clicked a marketing link or typed the URL.**

## What that has already caused

* [PRP-186](https://linear.app/axishousing/issue/PRP-186/manager-signup-collects-no-phone-number-on-the-hub-path-only-the) — no phone on the hub path, so the manager SMS work number can never be verified for anyone who came through that door. Fixed by adding the field, but the divergence that allowed it is untouched.
* [PRP-174](https://linear.app/axishousing/issue/PRP-174/hub-signup-missing-manager-phone-blocks-smstour-workflows) — the same bug, previously, closed by routing *marketing links* through the trial form. It came back through the other door.
* [PRP-173](https://linear.app/axishousing/issue/PRP-173/create-account-ignores-roletier-query-params-from-partner-pricing) — role/tier query params ignored on one path.
* Plan state differs: one door starts a trial, the other does not, so two managers can exist in different billing states depending on how they signed up.

The pattern is clear: every fix lands on one door and the other keeps diverging. Three tickets for one underlying split.

## Proposed

Pick **one** create surface and make the differences data, not separate components:

* One form, one API. Fields shown by chosen role; role picked *in* the form or carried by the URL, not after.
* The trial/tier decision becomes a parameter, not a different code path.
* `/auth/get-started` remains only for accounts that genuinely arrive without a role (OAuth).

## Acceptance

* One component and one endpoint create a manager, whatever the entry URL.
* A manager created from any entry point has: role, phone, and the same plan state.
* A test asserts the two entry URLs produce equivalent accounts.
