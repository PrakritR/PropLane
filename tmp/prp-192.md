## Description

Surfaced while resetting the test accounts to a blank slate, 2026-09-04.

## The gap

There is no script or route that removes an account and everything it owns. Doing it by hand meant discovering the dependency order the hard way and writing deletes across roughly **forty** tables, in four transactions, because foreign keys reject the obvious order:

* `gl_journal_lines` → `ledger_entries` / `security_deposit_ledger` → `gl_journal_entries` **before** anything else, or `auth.users` deletion fails on `ledger_entries_gl_journal_entry_id_fkey`.
* The whole vendor chain (`work_order_bids`, `work_order_vendor_offers`, `vendor_invoices`, `vendor_payouts`, `vendor_tax_profiles`, `vendor_availability_rules`, `vendor_invites`, `manager_vendor_records`) before `portal_work_order_records`.
* Then leasing, then scheduling/comms/documents, then finance settings, then `manager_property_records` last.

A type mismatch bites too: `landlord_id` is `uuid` on some agent tables and was assumed `text`, which fails mid-transaction with `operator does not exist: uuid = text`.

## Why it is worth a script

1. **Correctness.** Scoping is not just `manager_user_id` — rows also hang off `resident_email` (a **string**, not an id), `resident_user_id`, `vendor_user_id`, `owner_user_id`, and `landlord_id`. Miss one and orphaned rows survive with no owner, which is how ghost data appears in a "clean" environment.
2. **It will be needed for real.** Account deletion is a routine data-protection request. Today there is no code path that can honour one.
3. **It is repeated constantly.** Every QA reset re-derives it.

## Proposed

`scripts/delete-account.mjs <email> [--keep-login]`:

* Refuses unless the target project is dev, the way `check:mcp` does.
* `--keep-login` empties the account's data but leaves `auth.users` / `profiles` / `profile_roles` — the "blank slate for QA" case, which is what was actually wanted here.
* Prints a per-table count of what it will delete and requires confirmation.
* Derives the table list from `information_schema` so a new owner-scoped table cannot be silently missed.

## Acceptance

* Deleting an account leaves **zero** rows referencing it by any of the six scoping columns.
* A dry-run mode prints the plan without writing.
* Refuses to run against a non-dev project.
