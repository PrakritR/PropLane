## Description

Companion to [PRP-228](https://linear.app/axishousing/issue/PRP-228/pricing-model-for-the-dedicated-phone-number-what-we-charge-what-it) (phone-number pricing). Today almost every commercial number is a **constant in code**, so changing a price, comping an account, or running a pilot requires an engineer and a deploy.

## What is hardcoded today

```ts
MANAGER_TIER_MONTHLY_USD = { free: 0, pro: 20, business: 200 }   // manager-access.ts:14
```

Plus, spread across the codebase: property caps per tier, the 14-day trial length, application-fee defaults, the `$50` application-fee fallback ([PRP-203](https://linear.app/axishousing/issue/PRP-203/applicant-trapped-behind-a-phantom-dollar50-fee-with-no-payment-form)), and the service-fee payer rules.

**The one thing that is already done right** is `adminServiceFeeOverride` — staff-writable through `GET/PATCH /api/admin/manager-service-fee`, per-manager, with `saveManagerManualPaymentSettings` deliberately dropping any value a *manager* supplies. That is the pattern to generalise; it already proves the shape works.

## What the admin portal has today

`src/lib/portals/admin.ts` — Dashboard, Properties, Meetings, Feedback, Communication, Accounts, Settings. **There is no billing, pricing, or plan surface at all.** Everything commercial is invisible to staff.

## Proposed: an admin **Billing** section

**Global defaults** (one screen, versioned, audited):

| Setting | Today | Why staff need it |
| -- | -- | -- |
| Tier prices | hardcoded | a price change should not be a deploy |
| Property cap per tier | hardcoded | pilots, partners |
| Trial length | hardcoded | campaign experiments |
| Application-fee default | hardcoded | and **remove the** `$50` **fallback** ([PRP-203](https://linear.app/axishousing/issue/PRP-203/applicant-trapped-behind-a-phantom-dollar50-fee-with-no-payment-form)) |
| SMS allowance / overage | does not exist | [PRP-228](https://linear.app/axishousing/issue/PRP-228/pricing-model-for-the-dedicated-phone-number-what-we-charge-what-it) |
| Processing-fee payer default | per-manager only | set the platform default |

**Per-account overrides** — open an account in admin and set: plan, cap, trial end, fee payer, SMS allowance, comp status. Each with a **reason** field and an **audit trail** (who, when, before → after). The reason field matters: six months later nobody remembers why one account pays nothing.

## Processing fees specifically

The plan rule already exists and is documented (Free → resident pays; Pro → manager's choice, default resident; Business → can be absorbed by PropLane), resolved by `resolveServiceFeePayerFor` with precedence **staff override → property → manager default → resident**.

What is missing is **staff reach and visibility**:

1. **A screen.** The override is API-only today. Staff should see the effective payer for an account and change it, without curl.
2. **What it costs us.** When PropLane absorbs the fee (Business), that is real money with no dashboard. Show absorbed fees per account per month — otherwise the most generous plan is the least measured.
3. **Bulk/default control**, e.g. "absorb fees for all partner-tier accounts", instead of per-account clicks.
4. **Change the fee itself?** Today `residentProcessingFeeCents` is a strict pass-through of Stripe's real cost, deliberately never a markup. If a markup is ever wanted, it must be a **deliberate, visible, admin-set** number — not a constant someone edits. Recommendation: keep pass-through, and make that a stated product position rather than an implementation detail.

## Build order

1. **Read-only first** — surface the effective plan, fees, caps and usage per account. Staff currently cannot even *see* this.
2. Then per-account overrides with reason + audit.
3. Then global defaults.

Read-only is most of the value and carries almost no risk.

## Guardrails

* Every override is **staff-only**, exactly as `saveManagerManualPaymentSettings` already enforces — a manager must never be able to write their own pricing.
* Every change is audited.
* An unreadable plan must stay a **500 /** `planUnknown`, never a silent fall back to Free (AGENTS.md, plan-entitlements).
